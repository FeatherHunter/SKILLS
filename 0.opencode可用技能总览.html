本机自建技能

5 个 · 个人定制工作流

你自己写的工作流技能,覆盖记账、家务、健康、视频剪辑、作息五大领域。全部通过自然语言触发,AI 解析后调用 Python CLI 完成数据库读写。

饼干记账 个人

记账技能。支持记支出/收入/拍账单/改记录等写入操作,以及查今天/查日期/查分类/看月度/做统计等查询分析。查询类默认 invoke HTML 工作流。

触发方式
"记一笔 30 午餐" / "查今天" / "看月度"
自然语言直接说,系统自动识别写入还是查询。说「饼干记账 HELP」查能力速查。
居家管家 个人

家庭物品全生命周期管理。录物品/改物品/移物品/补物品/废物品/借物品/修物品,以及盘点/穿搭推荐/快递查询/账号密码管理等。

触发方式
"录物品 电动牙刷" / "查物品 牙刷" / "带物品 出差"
Python CLI 执行数据库读写,AI 解析自然语言和交互确认。录物品流程会生成 HTML 预览。
卡路里 个人

饮食热量、饮水、体重、运动、营养追踪与分析。覆盖记吃了/拍营养表/查热量/记体重/记运动/查健身计划/复盘本周等数十种操作。

触发方式
"刚吃了 一碗米饭" / "今天卡路里" / "记体重 65kg"
所有操作通过 Python CLI 写数据库,AI 负责解析自然语言。说「卡路里 HELP」查能力速查。
智剪工坊 个人

代码视频剪辑工作台,对标剪映(图形化)+ AI 扩展。30 个原子脚本 + 主体流程(阶段 0-5)。底层 ffmpeg + OpenCV + mediapipe + mmx matrix MCP。

触发方式
"剪辑" / "拼接" / "字幕" / "封面" / "智剪工坊"
支持剪辑/转场/调色/字幕/变速/水印/BGM/流水线/美颜/去水词/改写配音/AI 讲解/降噪/声源分离等。
作息管家 个人

作息记录与日程计划管理。支持查作息/查日程/商量计划/改计划/复盘/同步飞书日历等。新版事件型日程计划 + 飞书日历联动。

触发方式
"今天总结" / "规划明天" / "改计划" / "对比两个月"
所有操作通过 Python CLI 执行数据库读写。装了飞书 CLI (lark-cli) 后可一键同步到飞书日历。

mattpocock · Engineering

14 个 · 工程实践

来自 mattpocock/skills 仓库。Matt Pocock 基于"数十年工程经验"提炼的工程纪律技能。绿色"自动"标签 = 模型可主动调用,蓝色"手动"标签 = 需用户输入命令触发。

ask-matt 手动

技能路由器。不知道该用哪个 skill 时,问它即可,会基于本仓库的全部 skill 给出推荐路径。

触发方式
/ask-matt
入口 skill,先问它再做事。会告诉你该走 grill-with-docs → to-spec → to-tickets → implement 哪条主线。
setup-matt-pocock-skills 手动

为当前仓库初始化配置:issue tracker(GitHub/Linear/本地 markdown)、triage 标签、文档存放路径。用其他 engineering skill 前必跑一次。

触发方式
/setup-matt-pocock-skills
每个 repo 跑一次即可,配置写入 repo 内,后续 skill 自动读取。
grill-with-docs 手动

严苛盘问会话,在 sharpen 计划/设计的同时构建项目领域模型(写入 CONTEXT.md 和 ADR)。本仓库最火的 skill。

触发方式
/grill-with-docs
做任何变更前先用它对齐意图。每次问一个问题,等你回答后再问下一个,把决策树每个分支都走完。
to-spec 手动

把当前对话内容综合成一份 spec(PRD),发布到 issue tracker。不再盘问,只综合已讨论的。

触发方式
/to-spec
grill-with-docs 之后用,把对齐过的意图固化成可执行的 spec 文档。
to-tickets 手动

把 plan/spec/对话拆成一组 tracer-bullet 票据,每张票据声明自己阻塞的其他票据。本地 markdown 或真实 tracker 都行。

触发方式
/to-tickets
to-spec 之后用,把 spec 切成可独立交付的纵向切片,带依赖关系。
implement 手动

按 spec 或一组 tickets 实现工作。在 pre-agreed seams 处用 /tdd,结尾跑 /code-review 再提交。

触发方式
/implement
主流程的执行环节。定期 typecheck + 单测,结束时跑全测试套件。
triage 手动

把 issues 和外部 PRs 在 triage 角色状态机里流转:categorise → verify → grill → 写 agent-ready brief。

触发方式
/triage
把 PR 当作"带代码的 issue"统一处理,五个 canonical triage 角色流转。
improve-codebase-architecture 手动

扫 codebase 找"deepening opportunities"(把浅模块变深),以可视化 HTML 报告呈现,然后逐个 grill。

触发方式
/improve-codebase-architecture
每隔几天在 ball-of-mud 形成前跑一次,救回架构。
wayfinder 手动

规划"超出单个 agent session 容量"的大型工作:在 issue tracker 上画一张 decision tickets 共享地图,逐个解决直到目的地路径清晰。

触发方式
/wayfinder
"plan, don't do"。先 chart the way,不直接冲目的地。
prototype 自动

建一次性原型回答设计问题:状态/逻辑问题用终端 app,UI 问题用单路由切换的多套变体。

触发方式
"建个原型 sanity-check 一下" / "试一下这个 UI 长啥样"
模型在合适场景主动调用。原型是 throwaway,只为回答问题。
tdd 自动

测试驱动开发 red→green→refactor 循环。什么是好测试、测试放哪、反模式、循环规则,每轮都参考。

触发方式
"red-green-refactor" / "TDD" / "先写测试"
implement skill 会在 pre-agreed seams 处主动调用。每次循环前+中查阅。
diagnosing-bugs 自动

硬 bug 和性能回归的诊断循环:reproduce → minimise → hypothesise → instrument → fix → regression-test。非经明确理由不可跳阶段。

触发方式
"debug 这个" / "怎么不工作" / "这个很慢"
用户报告 broken/throwing/failing/slow 时模型主动调用。
research 自动

后台 agent 调研一个问题,基于高可信一手资料(官方文档/源码/spec/first-party API),把发现写入 repo 内 Markdown 文件并引用来源。

触发方式
"研究一下 X" / "调研 Y 的 API" / "帮我查文档"
后台跑,你可以继续干活,完成后给一份带引用的 Markdown。
domain-modeling 自动

主动构建和 sharpen 项目领域模型:挑战术语、造边缘 case、写 glossary 和 ADR。区别于"读 CONTEXT.md"的被动行为。

触发方式
"统一术语" / "记下这个架构决策" / grill-with-docs 内部调用
在改模型时(而非消费模型时)主动调用。
codebase-design 自动

deep module 设计的共享词汇表:大量行为藏在小接口后、clean seam、可测。给所有"设计/重构模块接口"的 skill 当通用语言。

触发方式
"设计这个模块接口" / "哪里放 seam" / 其他 skill 内部调用
不直接用,作为词汇层被其他 skill 引用。
code-review 自动

两轴 review:Standards(是否遵循 repo 文档化的编码规范 + Fowler smell baseline)和 Spec(是否忠实实现 originating issue/PRD),双 sub-agent 并行跑后聚合。

触发方式
"review since X" / "看看这个分支"
implement skill 结尾自动调用,也可独立用。
resolving-merge-conflicts 自动

逐 hunk 解决 git merge/rebase 冲突,追溯每方原始意图,优先保留双方意图,绝不 --abort。

触发方式
merge/rebase 冲突时自动触发
看冲突状态 → 找每方 primary source → 逐 hunk 解决 → 跑 typecheck/tests/format。

mattpocock · Productivity

5 个 · 通用工作流

非代码特定的工作流工具:对齐意图、跨 session 接力、教学、写 skill。

grill-me 手动

非代码版的严苛盘问。不停地问直到决策树每个分支都解决。每问一个问题,给你推荐答案。

触发方式
/grill-me
思考任何决策时都用,不是代码专属。一次只问一个问题,等你回答后再问下一个。
grilling 自动

grill-me 和 grill-with-docs 背后的可复用循环。事实性问题自己查环境,决策性问题问你并等答。

触发方式
grill-me / grill-with-docs 内部调用
一般不直接用,被手动 skill 包装。但你想直接 grill 时也能调用。
handoff 手动

把当前对话压缩成交接文档,让另一个 agent 接力。存到 OS 临时目录而非当前 workspace,包含"建议 skill"段落。

触发方式
/handoff 下一个 session 用来干嘛
不重复已在 specs/plans/ADRs/issues/commits/diffs 里的内容,只引用路径或 URL。
teach 手动

跨多个 session 教你一个新技能或概念。当前目录作为教学 workspace,学习状态在其中多个文件持久化。

触发方式
/teach 想学什么
stateful 请求,意图跨多 session 完成。教学进度记录在目录文件里。
writing-great-skills 手动

写/编辑 skill 的参考:vocabulary + principles 让 skill 可预测。核心是 predictability(每次走同一流程,而非产出同一输出)。

触发方式
/writing-great-skills
改 skill 前先查阅,bold 术语在 GLOSSARY.md 里有完整定义。

superpowers 内置

3 个核心 + 多个辅助 · 全局工程纪律

来自 superpowers@git+https://github.com/obra/superpowers.git 插件。system prompt 顶层加载 using-superpowers,强制要求"匹配 skill 必须先 invoke 再答"。下表只列你会高频触达的核心 + 工程纪律 skill,完整列表共 15+ 个。

using-superpowers 自动

已自动加载。所有对话开始前先走它:决定要不要 invoke skill。1% 可能适用就要 invoke,不允许 rationalize 跳过。

触发方式
自动,每条用户消息触发
不需要你操心,系统已强制加载。它告诉你"红旗清单"防止偷懒跳过 skill。
brainstorming 自动

创造性工作前必跑:做 features / 建 components / 加 functionality / 改 behavior 之前先探索用户意图、需求和设计。

触发方式
"加个 X 功能" / "改这个行为" / EnterPlanMode 前
process skill,优先级最高。先 brainstorm 再 implementation skill。
systematic-debugging 自动

遇到 bug / 测试失败 / 非预期行为时,提议修复前必跑。系统化定位根因,不许"猜一个 fix 试试看"。

触发方式
"修这个 bug" / 测试失败 / 行为奇怪
rigid skill,严格按步骤走。先 reproduce → 再 diagnose → 才 propose fix。
test-driven-development 自动

实现任何 feature/bugfix 前必跑。先写测试(红)→ 再写实现(绿)→ 重构。与 mattpocock 的 tdd 互补。

触发方式
"实现 X" / "加 Y 功能" / 写代码前
rigid,严格 red-green-refactor,不可省略。
verification-before-completion 自动

声称"完成/修好/通过"前必跑:必须先跑验证命令、确认输出,才可声明成功。evidence before assertions。

触发方式
即将说"搞定了" / 提交前 / 创 PR 前
不许凭感觉说"应该可以了"。必须跑 lint/typecheck/tests 给证据。
requesting-code-review 自动

完成任务、实现大功能、merge 前用:验证工作满足需求。会拉一个 reviewer sub-agent 独立审。

触发方式
完成大块功能后 / merge 前
与 mattpocock code-review 互补,这个偏"请求审查",那个偏"执行审查"。
writing-plans 自动

拿到 spec / 多步任务需求,动代码前用:写一份可执行的 implementation plan。

触发方式
复杂任务动代码前
配合 executing-plans / subagent-driven-development 在独立 session 执行。
dispatching-parallel-agents 自动

2+ 个独立任务(无共享状态、无顺序依赖)时用:并发派多个 subagent 加速。

触发方式
多个独立任务可并行
本会话中并发派发,适合 research / 多文件搜索等无状态任务。

使用方法

三种触发路径

理解"手动"和"自动"标签的差异,以及 skill 之间的优先级,是用好这套系统的关键。

手动触发 手动

蓝色"手动"标签的 skill 必须你显式输入命令才会启动。比如 /grill-with-docs、/tdd、/implement。

用法
直接输入 /skill-name [可选参数]
主要 orchestration 类 skill 都是手动,如 to-spec / to-tickets / implement / triage / handoff。
自动触发 自动

绿色"自动"标签的 skill 由模型在合适场景主动调用,你不用记。比如 brainstorming / tdd / diagnosing-bugs / research。

用法
自然语言描述任务,模型自行判断
"加个登录功能" → brainstorming + tdd 自动启动;"这个 bug 怎么回事" → systematic-debugging + diagnosing-bugs 自动启动。
优先级 规则

Process skill 先于 implementation skill。"建 X" → brainstorming 先,再 implementation skill;"修 bug" → debugging 先,再 domain skill。

顺序
brainstorming → writing-plans → tdd → verification
用户显式指令(CLAUDE.md / AGENTS.md) > superpowers skills > 默认 system prompt。优先级冲突时听用户的。
典型工作流:从想法到上线

1. 想法粗略 → /ask-matt 问该走哪条主线
2. /grill-with-docs 盘问 sharpen 意图,顺带写 CONTEXT.md + ADR
3. /to-spec 综合成 spec → /to-tickets 切成带依赖的票据
4. /implement 执行(在 pre-agreed seams 处自动调 /tdd)
5. implement 结尾自动跑 code-review,通过后 verification-before-completion 给证据
6. 大型工作超出单 session → /handoff 交接给下一个 agent

典型工作流:修一个难 bug

1. 用户说"这个不工作" → systematic-debugging + diagnosing-bugs 自动启动
2. reproduce → minimise → hypothesise → instrument → fix → regression-test
3. 修复时若涉及新逻辑,tdd 先写测试再改
4. verification-before-completion 跑测试给证据再声明修好

典型工作流:个人记账 / 健康追踪

1. 直接说自然语言:"刚吃了 一碗米饭 200g"
2. 卡路里 skill 识别为写入,Python CLI 写库
3. "今天卡路里" → 识别为查询 → invoke HTML 工作流生成可视化面板
4. "复盘本周" → 拉一周数据生成综合复盘 HTML
