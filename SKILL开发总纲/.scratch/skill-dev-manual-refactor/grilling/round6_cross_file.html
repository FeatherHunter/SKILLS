方法:审查报告没做的逐条交叉验证

审查报告自我反思承认:"读内容找矛盾有余,跨文件交叉验证不足。"我用 A 坐标(字面自洽)做它没做的事——把 9 个 .md 与 HTML 镜像、伪代码与实现、计数与条目逐条对比,找出审查报告完全没碰的 6 个新问题。

新发现 1 · SKILL.md 与 §04 原则清单不同步

新发现 跨文件 SKILL.md 核心行为规则只提原则 11 + 12,§04 实际有 13 原则
SKILL.md:10-18(⭐ AI 核心行为规则)

SKILL.md 的"AI 核心行为规则"章节只显式提了两条原则:

> **HTML-First(原则 11):** ...
> **HELP 唤醒词与场景契约(原则 12):** ...

原则 1-10 完全没出现在 SKILL.md 的"核心行为规则"里。

§04 实际原则清单

§04 有 13 原则(0-12):原则 0 何时不做 / 1 CLI 阻塞 / 2 1模板多参数 / 3 四段式 / 4 占位符注入 / 5 渲染器4步 / 6 改动前3问 / 7 Commit / 8 8反模式 / 9 命名不带版本 / 10 单工铁律 / 11 HTML-First / 12 输出路径约定。

A 坐标下的判定

SKILL.md 作为 AI 主入口,它的"核心行为规则"章节是 AI 读到的第一段行为约束。只提 11/12 = AI 以为只有这两条是"核心",其他 11 条原则是"次要"。但 §04 把 10(单工铁律)标"最高优先级",1(CLI 阻塞)也是硬约束。SKILL.md 的"核心行为规则"章节标题与实际内容不匹配——它应该是"AI 必须知道的 2 条关键原则"而非"核心行为规则"。

修复:SKILL.md 这一段要么改标题为"AI 须知的 2 条关键原则(HTML-First + HELP 契约)",要么补全引用所有 13 原则的速览。我倾向前者(标题精确化),因为 SKILL.md 不应该重复 §04 的完整原则清单(避免双重维护)。

修复:统一为"⭐ HTML 单工铁律(最高优先级)"。

新发现 3 · §05 SOP 步骤数 vs 附录 C 步骤数

新发现 跨文件 §05 SOP 9 步 vs 附录 C 7 步(ADR-0002 后仍残留)
§05:108-118(工程实施 SOP · 改一个 Skill 的标准顺序)

§05 列了 9 步:1 先读指导手册 / 2 画领域边界 / 3 列触发词 / 4 设计schema / 5 写硬规则 / 6 写CLI / 7 写集成 / 8 跑自检 / 9 验证HTML输出路径+命名

§06:47-59(附录 C · 通用改造顺序)

附录 C 列了 7 步:1 画领域边界 / 2 列触发词 / 3 设计schema / 4 写硬规则 / 5 写CLI / 6 写集成 / 7 跑自检

A 坐标下的判定

审查报告 P1-5 标记过这个(完全重复),建议删附录 C 改引用 §05。但审查报告没注意步骤数不同:§05 是 9 步,附录 C 是 7 步。§05 多了"先读指导手册"(步骤1)和"验证HTML输出路径"(步骤9)。

附录 C 的 7 步是 §05 9 步的子集(漏了首尾两步)。A 坐标下,删附录 C 改引用 §05 是对的,但要确认 §05 的 9 步是权威,附录 C 不能以"7 步版本"残留在任何地方。

修复:删附录 C 整节,改单行引用"→ 通用改造顺序见 §05 工程实施 SOP"。同时 §05 SOP 步骤 1"先读指导手册"措辞模糊(读哪本?),改"先读 §02 5 层骨架确认符合 6 大特性"。

新发现 4 · §02 6 大特性 vs §04 决策矩阵的覆盖盲区

新发现 跨文件 §02 6 大特性没全部进 §04 决策矩阵
§02 6 大特性

① 可识别 / ② 可验证 / ③ 可恢复 / ④ 可约束 / ⑤ 可联动 / ⑥ 可演进

§04:264-274(决策矩阵:CLI 输出 → 模板类型)

§04 决策矩阵只覆盖:单条记录 / 当日列表 / 多天趋势 / TOP N 榜 / 完整性检查 / 多维综合 / 计划vs实际。这些是数据形状维度,不是 6 大特性维度。

A 坐标下的判定

这不是"重复"问题,是覆盖盲区:§04 决策矩阵管"数据形状选模板",但 6 大特性里的"可恢复""可联动""可约束"在 §04 没有对应的决策矩阵。A 坐标下不要求 §04 覆盖所有 6 特性(§04 管可视化),但要求显式声明边界:§04 决策矩阵只管"可识别 + 可验证"维度的可视化,其他特性的可视化决策在哪。

修复:§04 决策矩阵标题加一句"本矩阵只覆盖数据形状→模板类型。可恢复/可联动/可约束的可视化决策见各自特性章节"。或者承认总纲不覆盖这些(沉默边界,与 ω 一致)。

新发现 6 · §07 场景字段数与 CONTEXT.md 不一致

新发现 CONTEXT.md 引入 §07 说 7 字段,CONTEXT.md 我写的是 7,但字段名口径要核对
§07:85-95(场景字段最小必填集)

wake_word / scenario_id / scenario_title / dimensions / prompt / status / result = 7 字段

CONTEXT.md(我刚建)

我写的:"最小必填 7 字段:wake_word / scenario_id / scenario_title / dimensions / prompt / status / result"

A 坐标下的判定

字段数一致(7),字段名一致。但 §07:97 说"7 个字段是契约级最小必填集;Skill 可扩展,但不准删减或重命名上述字段"。CONTEXT.md 我没写这条约束。这是 CONTEXT.md 自身的不完整——它作为术语表,应该把"不准删减/重命名"这条约束附在术语定义后。

修复:CONTEXT.md 的"场景"术语定义后,加一行"契约级最小必填,不准删减或重命名(§07)"。
