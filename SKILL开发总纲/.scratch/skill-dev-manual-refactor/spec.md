# SKILL 开发总纲 V1.0 重构 spec

> **For agentic workers:** 本 spec 由 grill-with-docs 会话合成。前置 ADR:`docs/adr/0001-a-coordinate-internal-consistency.md`(A 坐标优先)、`docs/adr/0002-remove-scale-flexibility.md`(删规模伸缩表)。前置术语表:`CONTEXT.md`。重构遵循 A 坐标——内部 100% 自洽优先于 AI 认知负荷。

## Problem Statement

SKILL 开发总纲 V1.0 是定义 Skill 设计/改造/演化规则的元规范,旨在指导 AI 开发和重构任何 Skill。但当前总纲**自身违反自己的硬规则**:HTML 镜像含 .md 中不存在的"6/8 通过"规则(违反钩子 1)、钩子数标题"6"实际 7、原则数标题"11"实际 13、规模伸缩表与"所有 Skill 都要 5 层"的设计哲学冲突、§05 与 §06 内容完全重复、架构图.html 是孤儿文件且自身有 3 处不一致、§07 引用死链、伪代码与实现不同步、多处计数/编号/措辞跨文件不一致。

一个连自己规则都守不住的总纲无法指导别人产出高质量 Skill。用户视角的问题:作者(用户)打开总纲准备用它指导 Skill 开发时,发现总纲自身充满自相矛盾,地基不稳,无法信任其产出的指导。

## Solution

按 A 坐标(内部 100% 自洽优先,ADR-0001)对总纲做系统性重构:清除所有跨文件不一致、删除与设计哲学冲突的内容(规模伸缩表 ADR-0002、附录 D、6/8 规则)、统一计数与编号、修复伪代码与实现的字面对应、删除孤儿文件(架构图.html)、清除死链、建立术语表(CONTEXT.md)和决策记录(ADR)。重构后总纲做到"任何一个零上下文 agent 逐条 grep 都找不到内部矛盾"。

## Testing Decisions

本重构是**文档工程**,不是代码工程。测试策略不用 pytest TDD,改用**逐条 grep 自洽校验**——A 坐标下"100% 自洽"必须有客观证据。

### 什么是好测试(文档工程版)

- 只测**外部行为**(跨文件一致性),不测实现细节(某个 .md 怎么写)
- 每个 user story 对应一条可机器执行的校验命令
- 校验命令用 grep / Select-String / 计数,不用断言框架

## Out of Scope

- **是否该 Skill 化的判定指南**:不在总纲范围(决策点 7 锁定 ρ + ω)。总纲沉默地不碰这个问题,任何地方都不加判据或边界声明
- **§04 决策矩阵对 6 大特性的全覆盖**:决策矩阵只管数据形状→模板类型,不管可恢复/可联动/可约束的可视化。A 坐标下不要求覆盖,但也不显式声明边界(与 ω 一致,沉默不碰)
