第一轮审查的问题

1. "原则 10 和 11 都标最高优先级"——过度解读

原则 11 标的是"必须"不是"最高优先级"，两者是互补关系，§04 有明确的关系表。我应该在第一轮就读到那个表。

2. "01 应合并入 02"——忽略了浅入口价值

文档分层不只是避免重复，也是给不同读者不同入口。01 作为"30 秒入门"有独立认知价值。

3. 没发现 HTML 和 .md 之间的内容不同步——最严重遗漏

第一轮读了 HTML 的前 100 行和 grep 结果，但没做逐条对比。如果做了，就会发现"6/8 通过"规则只存在于 HTML 中。这是审查方法论的根本缺陷——偏读内容找内部矛盾，没做跨文件逐条交叉验证。

4. 对 §05/§06 重叠的判断太粗

说了"高度重叠"但没逐条对比。实际有两组完全重复的内容，比第一轮判断的更严重。而且 §06 的"4 个 fail mode"标题错误，正是因为重复导致的"改一处忘另一处"。

5. 没发现架构图.html 是孤儿文件

第一轮读了它但没意识到它没被任何入口引用。审查时不应只关注文件内容，还应关注文件在文档体系中的位置——被谁引用？引用链是否闭合？

对抗式审查的价值

第一轮发现 7 个问题（3 确认 + 4 需修正），第二轮对抗式审查后：

  • 确认：3 个结论维持不变
  • 修正：4 个结论降级或改方向
  • 新发现：10 个第一轮完全遗漏的问题
  • 推翻：0 个结论被完全推翻

对抗式审查的核心动作：回到原始数据 → 对每个结论找反证 → 用 grep/ls 等工具硬验证 → 不信任"我记得"。

第一轮的根本缺陷：读内容找矛盾有余，跨文件交叉验证不足。对抗式审查补上了这个缺口。
