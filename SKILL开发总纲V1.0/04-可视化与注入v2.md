# 04 · 可视化与注入 v2

> **v2 = 资产化方案**。v1 = 原则 + 案例,AI 每次重新设计 → 反复返工。v2 = 可加载资产 + 决策树。

## v1 痛点(为什么改造)

- 60+ skill 唤醒词里只有少数有人工 HTML,其余 print
- AI 每次都"理解原则 → 重新设计 CSS / JS / 状态机" → 结果不稳定
- BUG 反复:占位符多次、`</script>` 断标签、PowerShell 乱码
- UI 经常不符合预期 → 多次返工

**根因**:当前是"原则 + 示例",AI 每次综合结果不稳定。

**v2 修复**:从"原则 + 示例" → "可加载资产 + 决策树",让 AI **复用**而非**重设计**。

## 第一性原理

> **HTML 页面不是数据源,也不是业务规则层。它只是用户和数据之间的"可视化操作界面"。**
>
> 只解决"好看、可交互、可复用",不解决"数据"和"规则"。

## 原则 0 · 何时**不**该做

| 类型 | 决策 |
|---|---|
| 单条 CRUD(add / update / delete) | ❌ |
| 高频但无视觉(快速回执) | ❌ |
| 后台管理(需权限 / 事务) | ❌ |
| 数据采集(数据即产物) | ❌ |

**判定**:唤醒词里 **≥ 5 个**含"多字段 + 多条目 + 视觉密度",才值得做。

## 11 原则 (10 + 1 + 1)

### 原则 1 · CLI 阻塞(最高优先级)

**CLI 不返回结构化 JSON → 模板一定做不出来。**

```python
def xxx(start, end, as_dict=False):  # ← 关键参数
    result = ...
    if as_dict:
        return {"status": "ok", "data": result, "message": "..."}
    print(...)  # ← 默认行为不变(向后兼容)
```

**铁律**:CLI 重构**永远**保持默认行为不变,否则破坏现有调用。

### 原则 2 · 1 模板多参数

N 个数据结构相同的唤醒词 → **1 模板 + N 参数**(不是 N 模板)。

满足 3 条件才用 1 模板:
- ✅ X 唤醒词数据 schema 一致
- ✅ X 唤醒词展示区域结构一致
- ✅ X ≤ 5(再多拆)

正例:1 个 `food_ranking.html` 服务 5 个榜单(高热量 / 低热量 / 频繁 / 高碳水 / 高蛋白)。

### 原则 3 · 模板四段式

```
首屏 (HERO)   → 标题 + 状态徽章 + 4-6 KPI 卡     (5 秒内定位现状)
主体 (BODY)   → 按维度分组的折叠块              (扫读而非滚动)
交互 (INTERACT) → 轻 JS(折叠 / 勾选 / 筛选)      (不引框架)
尾部 (TAIL)   → 复制回 AI + 回到顶部            (用户主动切回对话)
```

**5 状态必有**:正常 / 空 / 缺数据 / 错误 / 离线。

### 原则 4 · 占位符 + 注入(5 个必须)

```html
<!--INJECT-DATA-->    ← 恰好 1 次(注入器会校验)
<script>
window.__DATA__ = { /* 注入 */ };
</script>
```

| # | 必须 | 原因 |
|---|---|---|
| 1 | 占位符唯一 | 注入器可校验 |
| 2 | `</` 转义 `'<\\/'` | 防提前闭合 script |
| 3 | `typeof window.__DATA__ === 'object'` 守卫 | 防未注入白屏 |
| 4 | 5 状态 fallback | 防数据缺失空指针 |
| 5 | `escapeHTML()` 函数 | 防 XSS |

→ 实现见 [_assets/injector.py](./_assets/injector.py)
→ 模板骨架见 [_assets/template_skeleton.html](./_assets/template_skeleton.html)

### 原则 5 · 渲染器 4 步

```python
# 1. 拿 JSON(subprocess 列表传参,避开 PowerShell 乱码)
data = json.loads(subprocess.run(
    ['python', str(cli_path)] + args,
    capture_output=True, text=True
).stdout)

# 2. 读模板 + assert 占位符唯一
template = Path(template_path).read_text(encoding='utf-8')
if template.count('<!--INJECT-DATA-->') != 1:
    raise ValueError("占位符必须唯一")

# 3. 注入(转义 + 替换)
payload = json.dumps(data, ensure_ascii=False).replace('</', '<\\/')
output = template.replace(
    '<!--INJECT-DATA-->',
    f'<script>window.__DATA__ = {payload};</script>',
    1
)

# 4. 写副本(原模板不动)
Path(output_path).write_text(output, encoding='utf-8')
```

### 原则 9 · 命名不带版本

```
❌ review_template_v2.html       ← 暗示有 v1 和 v3 共存
❌ dashboard_v3_apple.html       ← 暗示有 v1 / v2 / dark 共存
✅ review_report.html            ← 一个功能 = 一个文件
✅ health_dashboard.html         ← 一个功能 = 一个文件
```

**为什么**:同一个功能只有一个文件可演进;版本号暗示"多个并存版本",实际应"迭代就替换"。

**例外**:真有 N 份并行方案(实验性),改名前缀叫 `experiment_xxx.html`。

### 原则 10 · ⭐ HTML 单工铁律(最高优先级)

#### 第一性原理推导

```
Layer 0 事实:
  ① LLM = HTTP API(远程服务)
  ② HTML = 浏览器渲染的文件(无服务端能力)
  ③ 当前架构 = 没有服务端中转 + 只有 IDE 进程内 agent

推导链:
  ① + ② + ③
    ↓
  HTML 与 LLM 之间没有通路
    ↓
  唯一路径: 用户手动承上启下
              HTML → 复制 → 粘贴 → AI 执行
    ↓
  设计约束: 所有过程型 HTML 都必须设计为"复制模板"
```

**结论**:HTML 是**单工设备**,永远是单向渲染。它不能反向触发 LLM。

#### 设计推论

| 推论 | 应用 |
|---|---|
| 任何"过程型"HTML 必须提供**复制按钮** | 用户的选择 / 操作必须有"出口"回到 AI |
| 复制内容含 **4 部分** | 让 AI 有上下文(场景 / 数据 / 动作 / 来源) |
| "采纳"按钮也走复制路径(短确认) | 保持一致性,不让用户困惑 |
| 永远不期望"用户不去操作就生效" | 现实约束,设计必须围绕这个 |

#### 判定

```
IF HTML 包含让用户做出选择 OR 操作结果的展示
   THEN 必须设计"复制 prompt"按钮 + "采纳"按钮
   ELSE 不需要(纯结果型即可)
```

#### 4 部分 prompt 模板

```
① 场景: <用户在 HTML 中做了什么>
② 数据: <用户看到的最终数据(修改后)>
③ 期望: <AI 应该执行什么 CLI 操作>
④ 来源: <HTML 数据来自哪个 CLI / 时间>
```

#### 反模式(HTML 自己做事)

| ❌ 反模式 | 失败原因 |
|---|---|
| "一键保存" / "一键替换" / "一键执行" | 用户点了 → HTML 调不到任何后端 |
| HTML 自己 `fetch()` AI API | 暴露 API key + 跨域 + 静态托管不可写 |
| HTML 调本地服务 localhost | 不存在的服务,用户机器配置不可控 |
| 隐藏"复制"按钮 | 用户不知道有这一步,流程断在 HTML |

### 原则 11 · ⭐ HTML-First(必须)

> **唤醒词命中 SKILL 后,若 SKILL 声明有 HTML 输出路径,默认行为 = invoke HTML 工作流。文字答是 fail mode,不是 fallback。**

#### 第一性原理

```
观察 1: SKILL 的 HTML 输出 = 公开契约的一部分
观察 2: 唤醒词命中 SKILL = 契约被调用
观察 3: 文字答(而非 HTML) = 隐性违约
推论:   HTML 路径优先,文字答仅作 fallback
```

#### 与原则 10 的关系

| 原则 | 关注点 |
|---|---|
| 原则 10 · HTML 单工铁律 | HTML **本身**的设计:不能反通 LLM |
| 原则 11 · HTML-First | AI **执行** SKILL 时:不要降级到文字答 |

→ 原则 10 约束 HTML 的"出向"(单向),原则 11 约束 AI 的"入向"(必须 invoke HTML)。

#### 判定流程

```
IF 唤醒词命中 SKILL
  AND 该 SKILL 声明有 HTML 输出(在 SKILL.md 或 .html 文件中可见)
  THEN 必须 invoke HTML 工作流
  ELSE(无 HTML 声明 OR invoke 失败)→ 才允许文字答
```

#### 反模式(AI 的偷懒路径)

| ❌ 反模式 | 失败原因 |
|---|---|
| "意思不太对/有偏差,先文字答" | 应判定:命中 SKILL 就 invoke,模糊让 SKILL.md 兜底 |
| "用户没说要 HTML,默认文字" | HTML 是 SKILL 契约的一部分,不需要用户重申 |
| "invoke 失败 → 文字答" | invoke 失败应保留 HTML 错误页,不是降级到文字 |
| "看着简单,文字就够了" | SKILL 文档已声明 HTML,AI 无权简化输出形式 |

#### 与 03 触发词设计 v2 联动

03 触发词设计要求"2-3 个自然语言变体"。原则 11 强制要求:
- 用户说"查询健身计划"(变体) → AI 必须按"查健身计划"(核心) → invoke HTML
- 变体在文档里是"等价调用",不是"需要确认的请求"

#### 与钩子 ⑥ Fresh Agent 验证的协同

FAT 协议测试矩阵每行 = (核心唤醒词 × 2-3 变体),任一变体被 AI 判定为"有偏差"并文字答 = **fail mode**,必须改 SKILL.md(补变体)再测。

## 设计模式全景(头脑风暴触发器)

> 总纲**不提供模板库**——而是给你一份"模式词典",开发时让你知道有哪些 HTML 设计模式可能存在,然后**自己头脑风暴**挑一个最适合的来设计。
>
> **为什么不给现成模板?**硬编码模板会限制你的想象。给你**模式词汇表**,你就能从零设计新模板,而不是抄骨架。

### 头脑风暴协议(动手前 3 步)

1. **列出 3-5 个候选模式** — 从上表扫一遍,挑可能适合的
2. **剔除明显不适合的** — 数据形状不匹配(例:树状数据配折线图 = 错配)
3. **挑 1 个最贴用户心智** — 不是"最好看的",而是"用户最熟悉的"

> **举例**:唤醒词"查今天饮食" → 数据 = 当日多餐列表
> **候选**:单卡列表 / 网格 / 时间线 / 看板
> **剔除**:网格(餐次不是矩阵)/ 时间线(一天太短)/ 看板(无状态分组)
> **选**:**单卡列表**(用户心智 = "今天吃了几餐")
> → 设计一个全新的单卡列表模板(**不抄现有**,从模式词汇出发)

### 原则 12 · HTML 输出约定(V3 · 2026-07 增)

> Skill 的 HTML 输出分两类:**A · 数据/过程**(80+ trigger 替用户查 / 跑)+ **B · HELP**(Skill 自描述能力目录)。两类共享路径 + 冲突 + env,命名形态不同。

#### 12.X 共同基础(12.A / 12.B 共享)

- 路径根:`$SKILLS_DATA_DIR/`
- Skill 子目录:`<skill 标识>_html/`(各 Skill 在 SKILL.md 决定,跨 Skill 不共享)
- 时区:UTC,格式 `YYYYMMDD_HHMMSS`
- 冲突:`_N` 自动后缀(N=1 起步,**绝不覆盖**)
- env var 优先级:`$SKILLS_DATA_DIR` > `$SKILLS_DB_PATH` > Skill 自带 fallback
- 显式 override:`--output <path>` 允许,绕过 `_N` 后缀
- SKILL.md §📌 输出位置 章节**显式引用本原则 12 + 标 12.A 或 12.B**

#### 12.A · 数据 / 过程 HTML 约定

**适用**:80+ render 脚本(查今天吃 / 体重趋势 / 落地健身计划 / 健康报告 等)

**路径形态**:
```
$SKILLS_DATA_DIR/<skill>_html/<command_cn>_<YYYYMMDD>_<HHMMSS>[_<N>].html
```

- `<command_cn>` 是 render 命令的中文名(继承 SKILL.md §触发词速查表字面)
- 例子:`calorie_html/今日饮食_20260727_080137.html`
- 例子:`calorie_html/查卡路里数据_20260727_103000.html`

**第一性原理**:每次触发产生**新数据** / **新进度**,文件名 = query 描述 + 时间戳。

#### 12.B · HELP HTML 约定

**适用**:单一 HELP 渲染脚本(`render_help_center.py`)

**路径形态**:
```
$SKILLS_DATA_DIR/<skill>_html/<skill 中文名>_HELP_<YYYYMMDD>_<HHMMSS>[_<N>].html
```

- 命名固定以 `_HELP_` 结尾(约定保留字,识别度高,grep 一抓就出来)
- `<skill 中文名>` 前缀来自 SKILL.md frontmatter 声明
- 例子:`calorie_html/卡路里_HELP_20260727_102849.html`
- 例子:`binggan_html/饼干记账_HELP_20260727_103045.html`

**第一性原理**:HELP 是 Skill **自我介绍**。文件名 = Skill 名 + HELP 保留字 + 时间戳 — 一眼看出"哪个 Skill 的哪次 HELP 输出"。

#### 12.4 文件名约束(12.A / 12.B 共享)

- 中文优先(继承 SKILL.md §触发词速查表字面)
- 不含文件系统保留字符 `/ \ : * ? " < > |`
- 不含 `\n` `\r` `\t` 控制字符
- 长度 ≤ 100 字符(超出 OS 会自动 OSError)

#### 12.5 强制项(Skill 必须满足)

✅ Skill 必须实现:
1. 路径形态遵守 12.A 或 12.B(分类)
2. `<command_cn>` / `<skill 中文名>` 命名遵守 12.4
3. `_N` 冲突不覆盖遵守 12.X
4. env var 兼容 12.X
5. `--output` 遵守 12.X
6. SKILL.md §📌 输出位置 章节显式引用本原则 12 + 标 12.A 或 12.B

#### 12.6 反模式(明示禁止)

- 硬编码绝对路径(如 `/mnt/d/.db/calorie_html/`,跨 OS 失败)
- 文件名带 `[v1]` `[v2]`(违反原则 9)
- 同名覆盖前不检查(违反 12.X)
- Skill 跨 `<skill>_html/` 共享子目录放 HTML(命名冲突)
- **HELP 输出用 12.A 命名**(丢失"自描述"语义)— 例:`calorie_html/HELP_20260727.html` 错
- **数据/过程输出用 12.B 命名**(`<skill>_今日饮食_<datetime>.html` 错位)— 例:`calorie_html/卡路里_今日饮食_20260727.html` 错

#### 12.7 与现有原则的关系

- 原则 9(命名不带版本):继承
- 原则 10(HTML 单工铁律):配合(输出后仍单工)
- 原则 11(HTML-First):配合(强制 render + send 不归原则 12 管)
