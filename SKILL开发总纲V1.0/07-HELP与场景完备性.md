## 第一性原理

```text
观察 1: 用户对一个 Skill 的第一印象 = 唤醒词命中后的第一次响应
观察 2: 唤醒词命中后,用户最常问的不是"怎么做",而是"你能做什么"
观察 3: Skill 文档只在开发者手里;用户手里只有触发词、HTML、AI 回复
观察 4: 50+ skill 的维护者各自维护自己的 HELP = 50+ 份不一致的速查表
推论:   每个 Skill 必须有 1 个 HELP 唤醒词 + 1 份权威场景资产 + 1 个 HTML 交付页
```

**一句话**:Skill 不能"嘴上说自己能做 8 件事,实际 HTML 只展示 3 件,文档只写 5 件"。**场景完备性 = 唤醒词声明、场景资产、prompt、底层工作流、HELP HTML 五者一一对应,缺一即不合规。**

## 30 秒回答

| 问题 | 答 |
|---|---|
| 做什么 | 定义每个 Skill 的 HELP 唤醒词、场景资产、稳定 prompt、二态状态和 HTML 交付规则 |
| 怎么用 | 写 Skill 时:**先列场景清单**,再写 prompt,再写底层,最后生成 HELP HTML |
| 何时不读 | 写单条脚本 / CRUD / 不写 Skill 的工作(参见 06 附录 D) |
| 不做什么 | **不**规定具体 CLI 命令、不**暴露**数据库字段名、不**锁定** prompt 文案 |

## ⭐ 核心规则一览

| # | 规则 | 一句话 |
|---|---|---|
| 1 | **HELP 唤醒词专属化** | 每个 Skill 至少有 1 个 HELP 唤醒词(命名/变体由 Skill 自己决定,`{Skill名}HELP` 仅作示例) |
| 2 | **HELP 不展示自身** | HELP HTML 内不列出 HELP 唤醒词,避免死循环 |
| 3 | **HELP 命中走 HTML** | HELP 唤醒词命中 → 必须 invoke HTML 工作流(原则 11 HTML-First) |
| 4 | **场景穷举** | 业务唤醒词必须穷举所有合法场景,数量无上限,维度数量无上限 |
| 5 | **场景唯一事实源** | 场景资产是所有场景视图与 HELP HTML 的**唯一**规范事实源,其他视图均为派生物 |
| 6 | **prompt 抽象** | prompt 表达用户意图 + 预期结果,不暴露 CLI / DB / Python / 模板路径 |
| 7 | **二态状态** | 无状态 = 可用;`【待开发】` = 不可执行,但仍展示完整 prompt |
| 8 | **待开发铁律** | 用户复制待开发场景的 prompt 发送给 AI,AI 必须停并明示待开发,不准绕过 / 假装 / 降级 |
| 9 | **HTML 完整交付** | HELP HTML 必须展示全部业务唤醒词 + 全部合法场景;空 / 失败不准静默 |
| 10 | **大规模可用** | 场景多时可折叠 / 搜索 / 定位;窄宽屏 / 横竖屏 / 触摸 / 剪贴板降级全要验证 |

## 1 · HELP 唤醒词

每个 Skill 必须登记至少 1 个 **HELP 唤醒词**,用作该 Skill 唯一的能力速查入口。HELP 唤醒词记入 SKILL.md 的触发词声明,本身不是普通业务词;HELP 自身不得出现在它生成的 HELP HTML 中,以免循环。HELP 命名、变体数量和位置由 Skill 自定,详见设计稿。

HELP 命中后必须 invoke HELP HTML;未就绪是违规/待开发状态,不能用文字替代 HELP HTML。允许用简短文字告知"该 Skill HELP 中心未就绪",这属于状态告知而不是 HELP 契约的绕过。

## 2 · 场景完备性 · 业务唤醒词的场景清单

```text
观察: 一个业务唤醒词在不同维度下会产生多条合法执行路径
       例:"查今天吃" = 查全部 / 查高热量 / 查低蛋白 / 按热量排 / 按时间排 ...
推论: 每个业务唤醒词必须穷举所有合法场景,场景数不设上限
       维度数量也不设上限:时间范围 × 查询视角 × 对比方式 × 筛选条件 × 排序方式 × 数据健康度等
```

### 2.1 场景资产管理

```text
<skill>/references/scenarios.<skill-chosen-format>  ← 唯一规范事实源(路径 / 格式自定)
                 ├─ 可选的人类可读视图        ← 派生物
                 ├─ 可选的机读视图            ← 派生物(HELP 渲染器读取)
                 └─ HELP HTML                 ← 派生物(由场景资产 + 模板 + 渲染器生成)
```

场景资产作为 Skill 开发时必须产出的正式文档资产和 HELP HTML 的唯一事实源,人类视图、机读视图和 HTML 都是从它生成的派生物。**不准手工维护独立的 HELP HTML 副本**(理由参见 [04-可视化与注入v2.md §原则 4](./04-可视化与注入v2.md))。

### 2.2 场景字段(最小必填集)

```text
{
  wake_word       "查今天吃"               // 关联业务唤醒词
  scenario_id     "food_today_all"          // 稳定 ID,跨版本不变
  scenario_title  "查看今天所有饮食记录"    // 用户可读标题
  dimensions      { /* 按领域合法维度 */ }  // 实际涉及的维度,不必填满示例
  prompt          "请帮我..."               // 稳定用户意图(详见 §3)
  status          "" | "【待开发】"          // 二态状态,详见 §4
  result          "会显示今天的饮食..."     // 仅描述用户预期结果
}
```

7 个字段是契约级最小必填集;Skill 可扩展,但**不准删减或重命名**上述字段。

### 2.3 场景示例(非强制)

时间范围维度可参考的取值并非强制最低枚举,具体由 Skill 领域决定:

```text
今天 / 昨天 / 本周 / 上周 / 本月 / 上月 / 本年 / 去年同期
去年次月同期 / 最近 N 天 / 自定义区间 / 双区间对比
无数据 / 数据缺失 / 数据不足 / 错误 / 离线(仅在依赖外部资源时适用)
```

跨月 / 跨年 / 闰年边界由 Skill 自己实现相对时间换算(参见 [03 §相对时间换算](./03-触发词设计v2.md)),不在本章节规定实现细节。

## 3 · 稳定 prompt · 抽象用户意图

prompt 必须只表达**稳定的用户意图**和**预期结果**,不暴露任何实现细节:

| 类型 | 反例(❌) | 正例(✅) |
|---|---|---|
| CLI 子命令 / 路径 | `python scripts/food.py list` | "请帮我看看今天吃了什么" |
| 数据库字段 | `SELECT * FROM foods WHERE kcal>500` | "看看今天热量最高的前几个" |
| Python 文件 / 模块 | `render_food_ranking.py` | (不出现) |
| 模板路径 | `templates/food_ranking_high.html` | (不出现) |
| 环境变量 / 数据库表名 | `$SKILLS_DB_PATH` / `food_log` | (不出现) |
| 易变调用步骤 | "步骤 1:query,步骤 2:..." | "查完按时间顺序给我看" |
| 错误码 | `status=200` / `ERR_DB_EMPTY` | (不出现) |

底层实现细节留在 Skill 内部(`SKILL.md` 路由规则、`references/`、`scripts/`、`validators.py`、`templates/`),**实现层可以重构,prompt 不必随之失效**。

AI 收到复制 prompt 后的执行方式:先加载该 prompt 对应的 Skill,在唯一场景资产中定位 `wake_word + scenario_id + status` 记录,再按场景工作流执行或按 §4 停止并告知。

## 4 · 二态状态 · 无状态与 `【待开发】`

| 状态值 | 含义 | HELP HTML 渲染 | AI 行为 |
|---|---|---|---|
| `""`(空字符串) | 可用 | 正常展示,可一键复制 | 按 prompt 执行 |
| `"【待开发】"` | 不可执行 | 醒目标注,默认可见 | **必须停**,允许简短告知,不准绕过 / 假装 / 降级 |

**为什么必须有 `【待开发】`**:Skill 开发的现实是登记的唤醒词数 ≥ 已实现工作流。未实现的唤醒词若不显式标注,用户在 HELP HTML 复制 prompt 后 AI 假装执行 = 用户被骗。**显式标注 = 告诉用户"这块还没好"**。

- `status` 是场景资产内部的契约元数据,**不准**也不**需要**拼入用户复制的 prompt;复制内容保持稳定、纯净。
- 待开发场景仍必须展示完整字段(尤其是 prompt 与复制按钮),只做视觉区分,不准折叠隐藏或删除。
- 退出路径:`status = ""` 仅在唤醒词声明、场景资产、prompt、底层工作流、HELP HTML 全部就绪时才能变更(详见 §5)。

## 5 · HELP HTML 交付规则

HELP HTML 必须:

- 展示除 HELP 自身外的全部业务唤醒词;
- 展示每个唤醒词的全部合法场景,**不准删减合法场景**;全部场景必须保留;页面可按规模折叠/分组/搜索;
- `wake_word`、`scenario_title`、`【待开发】` 标记(如适用)、复制按钮始终默认可见;`dimensions/result/prompt 详情` 可以折叠但必须能展开查看;
- 每场景独立复制按钮,提示成功/失败;剪贴板 API 不可用时提供降级机制或手动复制提示;
- 覆盖正常 / 空 / 缺失 / 错误 fallback;离线态按页面外部依赖判定,纯本地页面允许记为 N/A;
- 同时适配手机和 PC:窄宽屏、横竖屏、触摸输入、长 prompt 换行、剪贴板降级,真实验证而非仅桌面;
- 失败和空数据不准静默空白。

HELP HTML 不展示:

- HELP 唤醒词自身;
- CLI 命令 / 数据库字段 / Python 文件 / 模板路径;
- 仅用作状态告知的纯文字列表(这违反 HELP 契约,不是合法 HELP)。

## 6 · 开发完成判定 · 五者一一对应

```text
① SKILL.md 唤醒词声明
   ↓ 必须一一对应
② 场景资产(唯一规范事实源)
   ↓ 每个场景必含 7 字段
③ 稳定 prompt(场景资产内)
   ↓ AI 命中后 invoke
④ 底层工作流(CLI / 模板 / 渲染器)
   ↓ 渲染
⑤ HELP HTML(用户手中唯一真相)
```

未完成任意一项,该场景标 `status = "【待开发】"`,在 HELP HTML 同步标注。**HELP 自身排除在业务场景清单之外**;HELP 中心未就绪时不允许用文字伪装。

FAT 适用方式以 [05-工程仪式.md §FAT 协议判定矩阵](./05-工程仪式.md) 的统一规则为准,本章不新增或改写 §05 的具体阈值/豁免条件。

## 7 · 与既有章节的协同

- **02 / 05 通过引用把场景完备性契约纳入验证**,但不在 07 直接改写它们的具体条目;
- **03**:业务唤醒词仍按 4 元组设计,登记前应先穷举场景并写入场景资产;
- **04**:HELP HTML 仍继承 4 段式、占位符、注入、单工铁律和 HTML-First;场景资产唯一事实源与提示符占位符一致;
- **05**:写 HELP 模板时沿用 HTML SOP,再叠加 07 的契约验收;
- **06**:3 维度评估、4 Phase 模式仍适用;新 Skill 改造时同步评估 HELP 资产产出。

## 8 · 反模式 · 不要做

| # | ❌ 反模式 | ✅ 正解 |
|---|---|---|
| 1 | HELP 唤醒词数量随意 | 每个 Skill 至少 1 个,具体数量与命名由 Skill 自行决定 |
| 2 | HELP 命中后文字答 | invoke HELP HTML(原则 11) |
| 3 | HELP HTML 展示 HELP 自身 | 死循环,移除 |
| 4 | 场景清单只在 SKILL.md 里口头描述 | 必须产场景资产(组织方式自定) |
| 5 | 手工维护 HELP HTML 副本 | 只能由场景资产 + 模板 + 渲染器生成 |
| 6 | prompt 暴露 CLI / DB / 文件路径 | 抽象到"用户意图 + 预期结果" |
| 7 | 未实现能力不标 `【待开发】` | 必须显式标注,不准伪装 |
| 8 | `【待开发】` 场景被 AI 假装执行 | AI 必须停 + 明确告知,不绕过 / 假装 / 降级 |
| 9 | HELP HTML 上 `【待开发】` 场景被隐藏 | 仍必须展示完整字段,仅视觉区分 |
| 10 | HELP HTML 加载失败静默空白 | 4 类 fallback 必须覆盖 |
| 11 | 场景数量被人为删减 | 全部场景必须保留;页面可按规模折叠 / 分组 / 搜索 |
| 12 | "全部复制"按钮 | 每场景独立复制按钮 |
| 13 | 复制按钮不提供反馈 | 复制成功必须有视觉反馈 |
| 14 | HELP HTML 不验多端 | 手机和 PC 必须验证;具体型号由项目决定 |

## 9 · 最小可行 HELP 资产清单

```text
1. SKILL.md          登记 HELP 唤醒词与跨 Skill 路由
2. 场景资产          唯一规范事实源(路径 / 格式 / 组织自定)
3. HELP HTML 模板    路径 / 文件名自定
4. HELP 渲染器       实现语言 / 路径自定
5. 测试              校验场景资产 schema + 复制按钮 / fallback / 多端行为
```

完成判定:§10 自我检查全部 ✅ + FAT 通过。
