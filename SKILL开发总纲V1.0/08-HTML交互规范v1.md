# 08 · HTML 交互规范 v1(跨技能通用契约)

> 状态:2026-08-04 由居家管家 v2.0 规格讨论定稿(wayfinder #54 / G7 #65 / SM1 #68)
> 适用:本仓库全部 SKILL(卡路里/备忘录/作息管家/饼干记账/私家大厨/居家管家/智剪工坊)
> 定位:HTML 单工铁律(§原则 10)与 HTML-First(§原则 11)之下的**交互层规范**——用户拿到 HTML 后的一切交互模式

## 0. 第一性

用户在对话中拿到 HTML 后,所有动作本质只有三种:**看(消费信息)、复制(带回对话)、点(本地只读交互)**。本规范定义:HTML 提供哪些流程形态、统一骨架、标准能力、按钮语义。

## 1. 交互流程 8 类

| # | 流程 | 说明 | 典型场景 |
|---|------|------|---------|
| 1 | 查看 | 卡片/列表/详情/图表/报告 | 查物品/看详情/统计/复盘 |
| 2 | 采集 | 字段表单(预填度 0→100% 连续;全预填 = 样式只读但可修改) | 录入/记一笔/记一餐 |
| 3 | 选择 | 单选/多选/二元批准(确认·合并 or 新建·消歧) | 同名选择/写操作确认 |
| 4 | 回执 | 成功(结果+diff+撤销)/失败(原因+重试)/错误 | 所有写操作后 |
| 5 | 向导 | 多步流程(查看+采集+选择的序列编排,含步骤条/返回) | 初始化/批量导入 |
| 6 | 对比 | before→after/并排/趋势 | 改物品/合并/复盘 |
| 7 | 导航 | HELP:目录+搜索+复制 prompt | HELP HTML |
| 8 | 转移 | 复制数据/prompt/日志 + 下载文件 | 全局动作层 |

## 2. 通用骨架

```
┌─────────────────────────────────────────┐
│ 头部:场景名 + 唤醒词 + 时间戳 + 流程阶段指示 │
├─────────────────────────────────────────┤
│ 内容区(按流程类型渲染,支持标准能力):      │
│   · 呈现型:卡片/列表/详情/图表            │
│   · 采集型:字段表单(预填度 0-100%)        │
│   · 选择型:单选/多选/选择器              │
│   · 对比型:before→after                  │
├─────────────────────────────────────────┤
│ 顺路提醒区(按上下文注入,可选,可空)        │
├─────────────────────────────────────────┤
│ 动作区(按阶段出按钮):                    │
│   · 采集阶段:复制填写结果(prompt)→发AI    │
│   · 确认阶段:确认写入/修改/撤销           │
│   · 结果阶段:复制数据/复制日志/下一步/下载 │
└─────────────────────────────────────────┘
```

- **页脚(联系作者)仅 HELP HTML 提供**;业务 HTML 不放页脚
- 流程阶段指示:填写 → 确认 → 执行/已完成(用户知道自己在流程哪个位置)

## 3. 内容区标准能力(所有 HTML 可选具备)

1. **本地只读交互**:筛选/折叠/排序/分页(JS 纯前端,不写库,与单工不冲突)
2. **敏感字段脱敏**:默认遮蔽(****),点击/复制时提示(凭证类场景必用)
3. **勾选模式**:勾选 → 复制选中数据(精准批量)/ 勾选 → 复制批量操作 prompt
4. **复制数据格式选择**:JSON / CSV / 纯文本(用途不同:发记账 vs 存档)

## 4. 按钮语义(统一契约)

| 按钮 | 复制内容 | 用户拿去 |
|------|---------|---------|
| 确认/修正/撤销/下一步 | 带参数的后续 prompt | 发给 AI(单工闭环) |
| **预告式(资源动作)** | **指令 + 【资源即将发送:】占位**——「【为 X 更换主图,照片即将发送:】」 | 发给 AI → AI 进入等待态 → 用户随后发照片/文件 → 收到即执行 |
| 复制数据 | 结构化数据(JSON/CSV/文本) | 自己拿去用(存档/分享/记账) |
| 复制日志 | 思考链/数据结构/调用脚本/CLI | 发给开发者/自己排障 |
| 下载 | 文件(CSV/JSON) | 自己拿去用 |

- **复制数据 + 复制日志 = 全部 HTML 硬标准**(无一例外)
- ❌ 无「复制摘要」按钮(用户裁决 2026-08-04)

### 预告-等待-接收模式(2026-08-04 新增)

**设计任何场景按钮时,先问:「这个动作需要用户提供资源(照片/文件/语音)吗?」**

- **需要** → 按钮复制**预告式 prompt**:指令 + 【资源即将发送:】占位(例:「【为物品 X 更换主图,照片即将发送:】」)
  - 用户:复制 → 粘贴给 AI(消息 1 = 指令预告)→ IM 选图发送(消息 2 = 资源)
  - AI:收到预告 → 进入「等待资源」态(该资源 ≠ 待处理素材,不等「发完了」)→ 收到资源即执行
- **不需要** → 普通 prompt

**与图片接收契约的互补**:图片接收契约 = AI 被动攒图(图无指令);预告模式 = AI 主动等图(指令先行、指定用途)。两者消除「这张图是干嘛的」歧义。

### 本地操作变更 = 统一确认(2026-08-04 新增)

- 本地只读交互(筛选/折叠/排序/分页)本身不写库;若操作会产生**持久化变更**(如照片排序 → 主图变更),HTML 提供**「确认变更」按钮**——普通确认式(非预告式):复制 prompt 含变更内容(例:「新顺序:图3→图2→图1,主图变更为图3」)→ AI 写库 → 回执
- 区分:本地交互(视图变换,无按钮)/ 确认变更(持久化,复制 prompt)

## 5. 输出双通道(与 §原则 11 互补)

每次交付 HTML,**必须额外一句话总结结果**(文字一句话 + HTML 详细呈现),不能只丢 HTML 或只丢文字。

## 6. 状态覆盖与降级

- 5 状态覆盖:正常 / 空 / 缺数据 / 错误 / 离线(总纲 §4 段式模板既有约定)
- HTML 生成失败 → 优雅降级:结构化文本 + 错误回执(操作名/关键数据/失败原因/建议下一步)

## 7. 图片接收契约(跨技能通用行为契约)

> 适用所有收图的 SKILL(拍物品/拍营养表/传附件/传素材),IM 多图必然分批送达:

| 用户行为 | AI 行为 |
|---------|---------|
| 图 + 处理指令(同一上下文) | 立即处理该图 |
| 图,无指令 | 攒着(不解析不处理),回一行「收到第 N 张:xx」 |
| 「处理这些/发完了」 | 合并处理(多图合并预览/清单) |
| 「先别处理」 | 只接收不处理 |
