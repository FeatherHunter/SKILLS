# ADR-0002 · 删除规模伸缩表,所有 Skill 字面 5 层 5 文件 + 全套自检

## 状态
accepted

## 背景
原 §02(line 128-134)和 §01(line 48-58)有"规模伸缩表":微型(≤1 .py,3 层合并)/ 中型(2-5 .py,5 层完整)/ 大型(5+ .py,5 层+子模块)。设计初衷是"避免过度工程"。

重构 grilling 中,作者明确裁决:"无论规模大小都要专业、都要符合开发总纲要求"。翻译成 A 坐标语义:所有 Skill 无论 .py 数量,都必须满足 §02 全部 5 层 + 6 大特性 + 8 反模式 + 自检清单 + 改动前 3 问,没有"微型可简化"逃生口。

## 决定
1. 删除 §02 line 128-134(规模自检表 + 整节"规模自检"标题)
2. 删除 §01 line 48-58(规模伸缩表 + "判断标准"段)
3. §02 5 层自检清单(line 136-181)保留全量,加一句"所有 Skill 必须全跑,无规模分档"
4. §06 附录 D(何时不该 Skill 化)保留,在 §02 删表处加引用"连 5 层 5 文件都撑不起 → 不该 Skill 化,见 §06 附录 D"
5. HTML 镜像同步删规模伸缩相关段落

## 理由
1. **作者意图**:作者认为"专业"不分规模,小 Skill 也要 5 层 5 文件才算合规。
2. **A 坐标自洽**:规模伸缩表是"逃生口",逃生口存在 = 允许不自洽(微型可以不建 validators.py?可以不跑 FAT?)。删除后所有 Skill 统一标准,无歧义。
3. **与 §06 附录 D 不冲突**:附录 D 说"单条 CRUD 不该 Skill 化"——这不是"小 Skill 可简化",而是"有些东西根本不该叫 Skill"。两命题不冲突:删了伸缩表后,80 行的"记喝水"要么写 5 层 5 文件,要么别 Skill 化(走附录 D)。

## 考虑过的替代方案
- **重写伸缩表(职责不简化,实现可合并)**:微型 5 层职责全有但可写在 1 个文件里。被作者否决——他要"字面 5 层 5 文件",不接受文件合并。
- **精神符合(5 层职责不可省,文件可合并)**:被作者否决,理由是"精神"难机器校验,A 坐标下要字面可验证。

## 后果
- **接受的代价**:80 行的小工具,合规成本可能是功能的 4 倍(5 个文件 + 20 项自检 + FAT 9 步 + HELP 场景资产)。作者已确认接受这个成本。
- **级联修复**:§01 瘦身到 ~30 行(删规模伸缩段);§02 删整节;HTML 镜像删段落;架构图.html 已由 ADR 之外的决策 git rm。
- **新建 Skill 门槛提高**:用户遇到小需求,会选"写普通脚本不 Skill 化"(走附录 D)而非"建 5 层 5 文件"。这是作者接受的结果——总纲不为小工具服务,只为"该 Skill 化的"东西服务。
