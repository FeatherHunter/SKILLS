# Skill HELP 唤醒词与场景完备性设计

## 目标

为每个 Skill 建立一个专属 HELP 唤醒词。HELP 唤醒词不是普通业务唤醒词，而是 Skill 的系统入口：命中后生成并打开 HELP HTML，向用户展示该 Skill 全部正式唤醒词的全部合法场景，并为每个场景提供可复制的执行 prompt。

HELP 的核心目的不是增加一份帮助文档，而是解决 Skill 的三层断裂：

```text
Skill 能力很多
→ 用户不知道怎样准确表达
→ AI 可能误判、漏参数或走错流程
```

HELP HTML 由此成为稳定的人类操作入口、自然语言意图目录和 Skill 完整性验收入口。

## 设计边界

### HELP 唤醒词

- 每个 Skill 必须拥有一个专属 HELP 唤醒词。
- HELP 唤醒词必须登记在 Skill 的唤醒词声明中。
- HELP 唤醒词不作为普通业务唤醒词。
- HELP 唤醒词可以出现在 Skill 的唤醒词总表中，但不得出现在自己生成的 HELP HTML 场景清单中。
- HELP 命中后必须执行 HTML 工作流，而不是直接用文字罗列帮助内容。

### 场景完整性

唤醒词不能只代表一句模糊能力名称，而必须对应一套完整的场景契约。每个 Skill 开发或重构时，必须：

1. 设计唤醒词；
2. 头脑风暴并穷举该唤醒词的全部合法场景；
3. 为每个场景定义稳定的执行 prompt；
4. 实现底层 CLI 和完整工作流；
5. 对未完成场景添加醒目的 `【待开发】` 状态；
6. 生成 HELP HTML；
7. 检查唤醒词、场景、prompt、状态和实现是否一致。

场景数量不设上限。完整性高于页面大小、开发成本和场景数量；即使一个唤醒词最终产生一万个场景，也不得为了页面简洁而删减合法场景。

### 场景维度

场景维度不限制数量。以下仅为示例：

```text
时间范围 × 查询视角 × 对比方式 × 筛选条件 × 排序方式 × 数据状态
```

一个时间查询唤醒词不能只覆盖“默认最近一段时间”，还应根据该领域的合法语义展开今天、昨天、本周、上周、本月、上月、本年、去年同期、去年次月同期、最近 N 天、自定义区间、双区间对比、无数据、数据不足等场景。实际维度由各 Skill 的领域语义决定，可继续增加。

## 场景资产

场景清单是 Skill 开发时必须产出的正式文档资产，不是可选帮助文档。每个场景至少包含：

```text
wake_word       唤醒词
scenario_id     稳定场景编号
scenario_title  用户可理解的场景名称
dimensions      场景维度组合
prompt          可直接复制给 AI 的执行 prompt
status          空值=可用；【待开发】=不可执行
result          用户预期得到的结果
```

场景资产是 HELP HTML 的唯一事实来源。HELP 页面必须从场景资产自动生成，不允许手工维护一份独立的、容易过期的 HTML 副本。

“禁止手工维护 HTML”仅针对由场景资产生成的 HELP HTML，不改变总纲原有的 `SKILL.md` 与 Skill 文档 HTML 镜像同步规则。

## Prompt 规则

每个场景必须有独立、可复制的完整 prompt。prompt 应表达稳定的用户意图和预期结果，不应深入功能实现细节。

禁止在 HELP prompt 中暴露或依赖：

- CLI 命令；
- 数据库表名和字段名；
- Python 文件和内部函数名；
- 模板文件名；
- 可能随重构变化的调用步骤。

底层 CLI、数据库字段、模板文件、Python 脚本和内部工作流只存在于 Skill 的执行文档和实现层。未来底层重构时，只要用户意图没有改变，HELP prompt 不应随实现细节变化。

【待开发】场景仍必须展示完整的执行 prompt。用户复制该 prompt 发给 AI 后，AI 必须识别其唤醒词或场景状态，停止执行，并明确告知该功能待开发；不得临时绕过状态、假装完成或自行降级为另一套未声明流程。

## 状态规则

只采用二态规则：

- 无状态标记：表示该场景已经完整开发，可以正常执行；
- `【待开发】`：表示场景设计、CLI 或工作流尚未完成，不得执行。

用户触发 `【待开发】` 场景时，AI 必须停止执行并明确说明待开发状态。

## HELP HTML 交付要求

每个 Skill 的 HELP HTML 必须：

- 展示该 Skill 除 HELP 自身外的全部正式唤醒词；
- 展示每个唤醒词的全部合法场景，不设数量上限；
- 明确显示场景状态，`【待开发】`必须醒目；
- 为每个场景提供独立的 prompt 复制按钮；
- 复制内容可以直接发送给 AI；
- 复制成功后显示 Toast，至少说明已复制及对应场景；
- 对大规模场景提供多级折叠、搜索或其他可定位结构；
- 场景数量很大时仍保持可读、可定位、可复制；
- 数据为空、生成失败或场景缺失时不能静默显示空白页；
- 同时适配手机浏览器和 PC 浏览器。

响应式要求包括：

- 支持窄屏、宽屏和横竖屏；
- 手机端按钮适合触摸；
- 折叠、搜索、复制和 Toast 在移动端可用；
- 长 prompt 自动换行，不产生不必要的横向滚动；
- PC 端充分利用宽度，便于浏览大量场景；
- 至少验证手机视口和 PC 视口；
- 剪贴板 API 失败时提供降级复制方案和明确提示。

## 开发完成判定

Skill 的 HELP 契约和底层实现必须形成以下一致关系：

```text
唤醒词声明
↔ 场景资产
↔ prompt
↔ 底层工作流
↔ HELP HTML
```

未完成完整场景设计或底层工作流的能力，可以登记为正式唤醒词，但必须在 `SKILL.md`、场景资产和 HELP HTML 中以醒目的 `【待开发】` 标识；不得伪装成已完成能力。

任何新增、删除或修改唤醒词、场景、参数语义、CLI 或工作流，都必须同步检查场景资产和 HELP HTML 生成结果。
