## ⛔ 停止开发 · 技能互联路线已转交新仓 ilife

本 issue 关闭。**「技能互联」这条跨技能数据契约层的路线已经停止开发**。

### 新项目地址：https://github.com/FeatherHunter/ilife

技能互联要解决的是「多个技能互相读对方的数据」，本仓的方案是**跨技能契约层**：`PUBLIC_DOMAINS` 注册表（提供方）＋ 通用适配器（消费方）＋ 统一 JSON 信封 ＋ 组合表，中间绕了一层注册与适配。

ilife 把这一前提改掉了：技能被**重构为同一个 TypeScript 仓里的包**（`packages/skill-*`），所以跨技能协作变成**仓内直接的包依赖与类型契约**，不再需要跨仓注册表和通用适配器；同时 ilife 在此基础上**开发了 DSH 插件**（`packages/plugin-*-ilife`），由插件在 DSH 会话里提供技能能力。因此本仓这套跨技能互联方案不再演进。

所以对本 issue 的处理口径是：

- 本仓相关资产（`.scratch/cross-skill/` 的能力全景／场景矩阵／组合表原型 等）：**冻结**，作为历史决策档案保留，决策过程仍可回溯。
- 本 issue（含 6 技能消费方开发子票、校验器 v1.1 等）：**不会在本仓实施**。如果这类联动仍然需要，请到 [ilife 仓 issue 列表](https://github.com/FeatherHunter/ilife/issues) 重新提出。
- 迁移样板：`饼干记账/ilife-新仓落地-20260911/README.md`（跨技能共享在 ilife 侧是怎么落成包依赖的，可作对照）。

> 关闭依据（维护者指示 2026-09-12）：跨技能／公共组件／卡路里／作息管家／私家大厨／饼干记账／备忘录 相关的 issue 全部关闭，并向读者强调新项目地址。
