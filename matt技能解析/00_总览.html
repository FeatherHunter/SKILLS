04 · 跨技能反复出现的设计模式

① Router + Primitive 配对

ask-matt / grill-me = 极简 wrapper,引导到 grilling primitive。
用最小代码做到"入口分离 + 逻辑共用"。

② Wrapper + 组合引用

grill-with-docs = 7 行 wrapper,组合 grilling + domain-modeling。
"一行差异"产生新特性(无状态 vs 落痕)。

③ Explicit-Only Invocation

disable-model-invocation: true + allow_implicit_invocation: false
ask-matt / grill-me / handoff / implement / to-spec / to-tickets / setup / writing-great / diagnose / improve-codebase / triage / wayfinder / teach 等都强制显式触发。

④ Avoid-List · 禁用清单

codebase-design / domain-modeling / improve-codebase-architecture 都配 _Avoid_。
"Consistent language is the whole point"。

⑤ OS 临时目录

handoff / improve-codebase-architecture / research 都写到 $TMPDIR//tmp/%TEMP%。
不污染仓库,不进 git,自动清理。

⑥ "Confirm Before Write" · 写前确认

setup-matt-pocock-skills · to-spec · to-tickets · triage 都"让用户审稿后才写"。
写文件是终局动作,必须用户看过。

⑦ Pre-Agreed Seam

codebase-design / implement / tdd / to-spec / to-tickets 共享"测试位置在写之前就约定"。
同一思想在 5 处表达。

⑧ Reference, Don't Duplicate

handoff · to-spec · to-tickets 都"不复制已有 spec / ADR / commit 内容,只引用 path / URL"。
避免"摘要的摘要"失真。

⑨ "User Perspective, Not Implementation"

to-spec · to-tickets 都要求用用户视角描述,不是 layer-by-layer 实现。
spec/ticket 是意图存档,不是结构快照。

⑩ "Trust + Confirm Before Action"

triage 的 quick state override · resolve-merge 的"never --abort"
用户直接指令 → 信任 · 但 action 前 confirm。

⑪ "Inline Templates"

to-spec · to-tickets 把模板直接放在 SKILL.md,不引用外部文件。
模型一眼看到,无需跳转。

⑫ "Progressive Disclosure"

codebase-design 的 3 文件结构 · improve-codebase-architecture 的 HTML-REPORT.md · setup 的多个 tracker 模板。
主 SKILL.md + 附录分层。

05 · 5 大跨技能哲学

哲学 体现位置 核心表述
Predictability writing-great-skills (根 virtue) 同 process,不同 output。LLM 是随机系统,skill 是约束器。
Vocabulary Discipline codebase-design / domain-modeling / improve-codebase-architecture 用专门术语,禁用近似词。语言决定思维。
Context Hygiene ask-matt / handoff / smart zone 步骤 1-3 留在一个 unbroken context。超 smart zone → handoff。
Tracers, Not Slices tdd / to-tickets / wayfinder vertical 切片 / 每发探路 / 决策不交付
Plan, Don't Do wayfinder (主) · writing-great-skills (元) 产出决策不产出交付物。"想动手"= 边界信号。

08 · 总结 · 整体设计哲学

★ 一句话总结

Matt 的 skills 是一个高度模块化、约定式、可验证的工程化系统。每个技能:

  • 单一职责 — 每个技能只做一件事,且说清楚做什么
  • 可预测过程 — 即使 LLM 是随机的,skill 让过程可重复
  • 词汇纪律 — 用 codebase-design / domain-modeling 共享语言
  • 状态化留痕 — CONTEXT.md / ADR / learning-records / map,跨会话持续
  • 边界硬化 — never --abort · never invent · never duplicate
  • 显式触发 — 不让模型脑补调用

这 21 篇解析只是起点。每个技能都值得反复咀嚼,因为它们的设计哲学可以应用到任何"让模型更可预测"的领域 —— 不仅是软件工程,还有教学、研究、协作工具等。
