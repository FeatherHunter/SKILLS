--- name: handoff description: Compact the current conversation into a handoff document for another agent to pick up. argument-hint: "What will the next session be used for?" disable-model-invocation: true --- Write a handoff document summarising the current conversation so a fresh agent can continue the work. Save to the temporary directory of the user's OS - not the current workspace. Include a "suggested skills" section in the document, which suggests skills that the agent should invoke. Do not duplicate content already captured in other artifacts (specs, plans, ADRs, issues, commits, diffs). Reference them by path or URL instead. Redact any sensitive information, such as API keys, passwords, or personally identifiable information. If the user passed arguments, treat them as a description of what the next session will focus on and tailor the doc accordingly.

★ argument-hint

这是 argument-hint 在我们已解析技能里的首次出现。
它提示用户:"输入这个技能时,告诉我下一会话要干嘛"。把这句当作下一会话的目标描述,handoff 文档会据此定制。
这是一种"为下一个 agent 写 README"的工程化做法。

03 5 条规则详解

① SAVE TO OS TEMP DIR
"Save to the temporary directory of the user's OS - not the current workspace."
为什么不是工作区?工作区里已经有 specs / ADRs / commits。handoff 是会话间的桥,不该污染仓库。
② SUGGESTED SKILLS SECTION
"Include a 'suggested skills' section in the document, which suggests skills that the agent should invoke."
下一个 agent 一加载就能看到:你该用什么 skill。
③ NO DUPLICATION
"Do not duplicate content already captured in other artifacts (specs, plans, ADRs, issues, commits, diffs). Reference them by path or URL instead."
避免"摘要的摘要" —— 引用,不复制。
④ REDACT SENSITIVE
"Redact any sensitive information, such as API keys, passwords, or personally identifiable information."
脱敏硬规则。
⑤ TAILOR VIA ARGUMENTS
"If the user passed arguments, treat them as a description of what the next session will focus on and tailor the doc accordingly."
用户传参 → 下一会话目标描述 → 文档针对性裁剪。

05 路径策略 · 为什么写到 OS 临时目录?

❌ 工作区 (current workspace)
.scratch/handoff.md
.handoff/session-2026-08-01.md
docs/handoff/...
为什么不行:
· 污染仓库(commit 时要清理)
· 容易和 spec / ADR 混淆
· 多人协作时不该共享
✅ OS 临时目录
macOS:  /tmp/handoff-YYYYMMDD-HHMM.md
Linux:  /tmp/handoff-YYYYMMDD-HHMM.md
Win:    %TEMP%\handoff-YYYYMMDD-HHMM.md
为什么对:
· OS 级别干净,不和 git 交互
· 重启自动清,不残留
· 跨工作区可用(同一台机器)

06 handoff 文档应该长什么样?

5 条规则组合在一起,生成的 handoff 文档大概是这样(示意):

# Handoff · <DATE> · <NEXT_SESSION_PURPOSE>

Context

[1-2 段:上次会话在做什么,为什么要切走]

Current State

  • 已完成:[...引用 commit / spec / ADR,不重复内容]
  • 进行中:[...在哪,下一步是什么]
  • 卡住:[...已知障碍 + 已排除的方案]

Suggested Skills

  • /implement — 用于继续实现 ticket #N
  • /diagnosing-bugs — 用于 Phase 1 还在跑的 bug 调查
  • /to-spec — 若需要把这次访谈落成 spec

References

  • spec: docs/specs/feature-x.md
  • ADR: docs/adr/0007-event-sourcing.md
  • PR: github.com/.../pull/42
  • commit: a4f2c1d

Decisions Made

  • [决策 1]:因为 [理由]
  • [决策 2]:因为 [理由]
关键原则:references 里的所有 path / URL,下一个 agent 一加载就能 cat / open 看到原文。handoff.md 自己不复制那些内容,只做索引 + 决策摘要。

08 关键设计模式

Bridge Pattern · 桥接模式
跨会话靠"一份 markdown 文件"当桥。本会话写,新会话读。
Argument-Hint for Tailoring
argument-hint 字段提示用户传"下个会话用途"。文档据此裁剪,不是通用模板。
Reference, Don't Duplicate · 引用不复制
spec / ADR / commit 都已经存在,只引用 path / URL,不复制内容。避免"摘要的摘要"失真。
OS Temp Directory · OS 临时目录
不写工作区,写 OS 临时目录。避免污染仓库,自动清理,跨工作区。
Suggested Skills Section
handoff 文档必含 "Suggested Skills" 一节。新 agent 一加载就知道用哪些 skill。
Redaction as Hard Rule
API keys / passwords / PII 必须脱敏。不是建议,是硬规则。
Explicit-Only Invocation
disable-model-invocation: true + allow_implicit_invocation: false。handoff 不能被模型脑补出来,只能用户显式触发。

09 启发 · 我们可以抄什么?

★ 给跨会话工具设计的启示

1. argument-hint 让用户参与设计:技能参数是用户和下一个 agent 之间的契约。
2. 写到 OS 临时目录:不污染仓库,不进 git,自动清理。
3. 引用不复制:让已有 spec / ADR / commit 担任"内容源",handoff 只做索引。
4. Suggested Skills 让接手更顺:新 agent 一加载就知道用哪些 skill。
5. 脱敏是硬规则:不是建议。
6. 显式触发:handoff 不能脑补。
7. 和 compact 划清:handoff 是 fork,compact 是 continue。
