02 全文 12 行

--- name: research description: Investigate a question against high-trust primary sources and capture the findings as a Markdown file in the repo. Use when the user wants a topic researched, docs or API facts gathered, or reading legwork delegated to a background agent. --- Spin up a **background agent** to do the research, so you keep working while it reads. Its job: 1. Investigate the question against **primary sources** — official docs, source code, specs, first-party APIs — not a secondary write-up of them. Follow every claim back to the source that owns it. 2. Write the findings to a single Markdown file, citing each claim's source. 3. Save it where the repo already keeps such notes; match the existing convention, and if there is none, put it somewhere sensible and say where.

03 3 大职责

04 "Primary Sources" 的分级

SKILL.md 第 10 行列举的"primary sources"有明确范围:

✅ 一手资源(High Trust)
  • 官方文档 (Official docs)
  • 源代码 (Source code)
  • 规范 (Specs / RFC)
  • 一手 API (First-party APIs)
❌ 二手资源(不要)
  • 博客对博客的转述
  • Stack Overflow 答案
  • 第三方教程
  • "10 个必知"列表文章
★ 设计哲学

"Follow every claim back to the source that owns it."
这句话是 research 技能的核心纪律。
模型常常引用"听说React 这样这样" —— research 不允许这种模糊引用。
每个 claim 必须能追到 owner。

05 后台 agent · 并行不阻塞主流程

06 输出文件示例

一个 research 产出的 markdown 大概长这样(示意):

# Research · Postgres 17 Logical Replication Behavior

Saved to: docs/research/postgres-17-logical-replication.md
Date: 2026-08-01 · Sources cited: 7 · Primary sources only: ✅

Question

Does Postgres 17 logical replication support DDL changes, and how does it differ from trigger-based replication?

Findings

Postgres 17 (released Sept 2024) added native DDL replication to logical replication via the ALTER PUBLICATION ... SET PUBLISH command and the wal_level=logical setting. [source: PostgreSQL 17 Release Notes, postgresql.org/docs/17/release-17.html]

Prior to 17, only DML changes (INSERT/UPDATE/DELETE) were replicated; DDL required pglogical or manual schema sync. [source: postgresql.org/docs/17/logical-replication.html §DDL Replication Caveats]

Replication slots track per-subscriber LSN and automatically advance. [source: src/backend/replication/slot.c, line 1247-1290]

Open questions

None — all claims traced to source.

07 "Match existing convention" 的实际做法

第 12 行第三条要求:写到仓库已有约定。常见约定:

约定 路径
docs/research/...最常见 · 适合长篇调研
.scratch/research/...临时性,不入主分支
adr/...当研究产出变成决策
CONTEXT.md新术语/定义入词汇表
没约定时:模型自己挑个合理位置,并在产出里明确告诉用户放哪了。否则用户找不到。

08 关键设计模式

Background Agent · 后台 Agent 委派
Spin up background agent 调研 → 主对话不被阻塞。把阅读外包。
Primary Sources Only · 仅一手资源
拒绝二手报道。每个 claim 必须追到 owner。这是可验证性的硬约束。
Citation Per Claim · 每条都引用
不是文末放 bibliography,而是行内引。每个 claim 旁带 source。
Convention Match · 适配已有约定
不发明新约定 · 不发明新目录。没约定时告知用户放在哪。
Single Markdown Output
单个 markdown 文件作为交付物。简单、可读、可分享。
Reading-Legwork Delegation
把人最痛的事("我去读 30 篇 RFC")外包给模型,人保留判断和决策权。

09 启发 · 我们可以抄什么?

★ 给调研流程设计的启示

1. 后台 agent 并行:阅读不阻塞主对话。
2. 一手 vs 二手:拒绝二手报道,所有 claim 追到 owner。
3. 行内引用:每条断言旁标 source,不是文末 bibliography。
4. 匹配已有约定:不发明新结构,没约定就告知。
5. 单文件交付:一个 markdown 搞定一切。
6. 外包阅读,保留决策:模型干苦力,人做判断。
