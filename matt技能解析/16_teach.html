03 Workspace 结构 · 7 类文件

teach 把当前目录当作学习 workspace,7 类文件各有分工:

MISSION.md
用户为什么想学这个。所有教学围绕此。
./reference/*.html
速查材料 · cheat sheets / syntax / algorithms / yoga poses / glossaries
RESOURCES.md
高质量学习资源列表(用于 acquire knowledge)
./learning-records/*.md
类 ADR · 关键洞察 + 难修正的教训,驱动未来 session
./lessons/*.html
主要交付物 · 一个 HTML 教一件小事
./assets/*
复用优先:stylesheets / quiz widgets / simulators
NOTES.md
agent 的 scratchpad · 用户偏好 · working notes

04 三大支柱 · Knowledge / Skills / Wisdom

SKILL.md §Philosophy:"To learn at a deep level, the user needs three things:"

📚 Knowledge

从高质量、高信任的资源捕获。

"Never trust your parametric knowledge." 模型自己的参数知识不可信。

🎯 Skills

通过 highly-relevant 交互式课程获得。

基于 knowledge,设计成 interactive feedback loop。

💡 Wisdom

与其他学习者 / 实践者互动获得。

模型可以试着答,但最终delegate 到社区(论坛 / subreddit / 实体课)。

★ Wisdom 必须 delegate

SKILL.md 第 117 行:"your default posture should be to attempt to answer — but to ultimately delegate to a community."
模型对 wisdom 类问题不要编。
推荐社区 / 论坛 / 实体班。
尊重用户"不想加入社区"的偏好。

05 Fluency vs Storage · 关键认知区分

⚡ Fluency Strength

当下提取知识的速度。

"我能立刻答出来" —— 可能给人虚假的精通感
🧠 Storage Strength

长期保留。

真正的目标
设计课程要建立 storage strength,办法:
  • Retrieval practice · 从记忆回忆
  • Spacing · 时间分布练习
  • Interleaving · 混合相关主题(仅技能练习)

06 Zone of Proximal Development (ZPD)

SKILL.md 第 81–89 行引入 Vygotsky 的 ZPD 概念:"challenged 'just enough'"

❌ CAN'T
too hard
✅ ZPD
just right
❌ TOO EASY
no growth

每个 lesson 都要落在用户的 ZPD 区间 —— 不太难,不太简单。

怎么算 ZPD?

读 learning-records(用户已经会什么)+ 推断 mission(用户想走到哪) → 找出"下一步该学什么"。

07 Lesson 设计原则

SKILL.md 第 47–61 行规定 lesson 的 6 条设计:

① 单一自含 HTML
一个 HTML 教一件小事 · 命名 0001-name.html 自增
② Beautiful / Tufte
typography 干净 · 用户会回看 review
③ Short + Quick
working memory 很小 · 不超载
④ Single Tangible Win
给用户一个具体可构建的成果
⑤ Anchor Links
HTML anchors 链到其他 lesson + reference
⑥ Recommend Primary Source
每个 lesson 推荐一个高质量 primary resource
关于 quiz 设计 (§110):
"For quizzes, each answer should be exactly the same number of words (and characters, if possible). Don't give the user any clues about the answer through formatting."
答案字数相同 → 不给格式线索。desirable difficulty 的具体应用。

08 Assets 复用优先

SKILL.md §67:"Reuse is the default, not the exception.
Before authoring a lesson, read ./assets/ and build from the components already there.
When a lesson needs something new and reusable, write it as a component in ./assets/ and link to it — never inline code a future lesson would duplicate."

第 69 行:"A shared stylesheet is the first component every workspace earns: every lesson links it, so the lessons look like one consistent course rather than a pile of one-offs."

★ 学习是渐进投资

workspace 随着时间长出 component 库,课程视觉风格一致。
不是先做完美再开课,而是做一门就赚一个 component。
这是"先求有,后求好"的工程化应用。

09 Mission · 教学的根本

SKILL.md 第 75–79 行写得很死:

If the user is unclear about the mission, or the MISSION.md is not populated,
your first job should be question the user on why they want to learn this.

Failing to understand the mission will mean knowledge acquisition is
not grounded in real-world goals. Lessons will feel too abstract.
You will have no way of judging what the user should do next.

Mission 可变

"Missions may change as the user develops more skills and knowledge. This is normal - make sure to update the MISSION.md and add a learning record to capture the change. Confirm with the user before changing the mission."

变更 mission 要 确认 + 写学习记录。又一次体现"决策留痕"的纪律。

10 参考文档 vs Lesson

第 124–136 行划了一条非常关键的边界:

  • Lessons rarely revisited later —— 用过就丢
  • Reference documents will be revisited —— 速查的精华
  • Reference 是 lesson 的压缩本质,quick reference 格式
  • 适合 reference 的:语法 / 算法 / yoga poses / exercises / glossaries
★ Glossary 是 reference 的最高形态

第 136 行:"Glossaries, in particular, are an essential reference. Once one is created, it should be adhered to in every lesson."
Glossary 一旦建,所有 lesson 都得用。这呼应了 codebase-design / domain-modeling 的 "Avoid-List" 纪律。

11 关键设计模式

Workspace-as-State · Workspace 即状态
技能自己建文件目录,把状态留在工作区。跨会话可继续。
Lesson = Single Win
每堂课一件事 · working memory 不超载 · 立刻有产出。
Reference Reuse Pattern
lesson 看过就丢,reference 反复回看。分清两个产物形态。
Component Library Earning
每堂课赚一个 reusable component,workspace 越长越一致。
Knowledge-Skills-Wisdom · 三层
知识从资源,技能从交互,智慧从社区。三层严格区分。
Storage over Fluency
课程要建立 long-term retention,用 desirable difficulty。
ZPD Targeting
每堂课在用户的 zone of proximal development。
Wisdom Delegate · Wisdom 委派
智慧问题不编,delegate 给真实社区。
Mission as Anchor · Mission 是锚
所有教学围绕 mission;mission 变了要确认 + 记录。

12 启发 · 我们可以抄什么?

★ 给教学设计的启示

1. Workspace 即状态:跨会话教学必须有落痕。
2. 三大支柱:Knowledge / Skills / Wisdom 严格区分。
3. Wisdom delegate:不编,推社区。
4. Fluency ≠ Mastery:课程要建立 storage strength。
5. ZPD 锚定:每堂课都"just enough challenging"。
6. Single Win:每堂课给一个具体产出。
7. Reference 复用:速查材料比 lesson 留得更久。
8. Component 渐进:每次赚一个,workspace 越长越好。
9. Mission 锚:教学围绕"为什么",mission 变要确认。
10. Never trust parametric knowledge:模型自己的知识不可信。
