02 核心哲学 · Plan, Don't Do

SKILL.md §13:"Wayfinder is planning by default: each ticket resolves a decision, and the map is done when the way is clear — nothing left to decide before someone goes and does the thing."

"The pull to just do the work is usually the signal you've reached the edge of the map and it's time to hand off."
★ 决策不交付

wayfinder 产出的是决策,不是交付物。
想"开始动手做"的冲动 = 地图边界的信号,该 hand off 了。
这是和 to-spec / implement 的根本区别 —— wayfinder 永远不做交付。

03 4 种 Ticket 类型

AFK
🔍 Research
读文档 / 第三方 API / 本地资源来 surface 一个事实。交给 /research subagent。当需要当前工作目录之外的知识时用。
HITL
🛠️ Prototype
造一个廉价粗糙的具体 artifact(大纲 / 草图 / stub / UI / logic code via /prototype)让讨论能 react。链接 prototype 作为 asset。
HITL
💬 Grilling
/grilling + /domain-modeling 一次一问。默认 case。
HITL or AFK
⚙️ Task
必须做才能决策的手动工作。注册服务 / 配置 access / 移动数据。唯一"做"而不是"决策"的类型。
★ HITL vs AFK 区分

§75:"HITL = human in the loop · 由人通过对话参与才能解决。模型永远不能代人那方(给自己回答的 grilling agent 违反这条)。"
这种伦理边界清晰:用户是另一方,不是可以替代的对象。

04 Fog of War · 战雾

SKILL.md §82–94 行是 wayfinder 最具特色的概念。

🌫️ Not Yet Specified · 战雾

你能感觉到有决策要来,但问不出来。
写成松散描述,等前沿推进时 graduate 成 tickets。
范围内,只是不够清晰。

测试:"现在能精确说出问题吗?" —— 不能 → fog
🎫 Ticket

问题已经够清晰,即使被 block。
写在 issue tracker,被 blocker 锁定。
范围内 + 够清晰。

测试:"现在能精确说出问题吗?" —— 能 → ticket
SKILL.md §88:"Fog or ticket? The test is whether you can state the question precisely now — not whether you can answer it now."
分流测试:能问清楚吗(不问能不能答)。

为什么"先问清楚再 ticket" 重要?

第 91 行:"Don't pre-slice the fog into ticket-sized pieces: it's coarser than a ticket, and one patch may graduate into several tickets, or none, once the frontier reaches it."

把 fog 切成 ticket 大小是常见错误。Fog 是粗粒度的,一块 fog 可能 graduate 成多张 tickets 或零张 ticket。强行切成 ticket 会过早收敛边界。

06 Out of Scope · 范围外

SKILL.md §95–102 行:Out of scope ≠ Fog。

维度 Fog Out of Scope
与目的地关系范围内 · 战雾会清除范围外 · 永不 graduate
清晰度不够清晰清晰被排除
如何处理等前沿推进 → graduate关掉 · 不进 Decisions-so-far
何时回归fog 清除时目的地被重新绘制时,作为新 effort

07 两种 Invocation 模式

📐 Chart the map · 制图
  1. Name the destination —— 跑 /grilling + /domain-modeling 定 destination
  2. Map the frontier —— breadth-first 烧烤 · 散开看整个空间
  3. Create the map(标 wayfinder:map) · Destination + Notes 填好,Decisions-so-far 空,fog 写到 Not yet specified
  4. Create tickets 你现在能指定的 · 第二 pass 连 edges
  5. Fire research subagents · 并行解决 research ticket
  6. Stop —— 制图是一个 session 的工作 · hand-resolves nothing
🚀 Work through the map · 走图
  1. Load the map(低分辨率视图,不是每个 ticket)
  2. Choose the ticket · 用户指定或第一个 frontier ticket · claim it(assign to self)
  3. Resolve it · zoom as needed · 用 Notes 里写的 skills
  4. Record resolution · post resolution comment · close issue · append context pointer
  5. 新浮现 tickets(create-then-wire)· fog graduate · 必要时 rule out of scope
★ One Per Session

§105:"never resolve more than one ticket per session — with the exception of research tickets."
每次会话只解决一个 ticket · research tickets 例外(可以批量)。
这是 smart zone 限制的具体应用。每 ticket 是单 session 容量。

09 Claim + Native Blocking

§67:"A session claims a ticket by assigning it to the dev driving the map, first, before any work, so concurrent sessions skip it. That assignee is the claim: an open, unassigned ticket is unclaimed."

§69:"Blocking uses the tracker's native dependency relationship — essential because it renders the frontier visually in the tracker's own UI, so the human sees what's takeable without opening the map."

★ UI as Truth

用 native tracker blocking(不是 body convention)的原因:
native blocking 在 tracker 的 UI 里视觉化展示 frontier。
用户不需要打开 map 也能看到"能接什么"。
把真理放在 UI 里 —— 让浏览比阅读更快。

10 关键设计模式

Plan Don't Do · 规划不做
产出决策不产出交付物。想动手 = 地图边界,hand off。
Decision Ticket
每个 ticket 解决一个决策。不是 build slice。回答即关闭。
Map as Index · Map 是索引
Map 是 index 不存内容。Decisions-so-far = 一行 gist + 链接到 ticket。决策只存一处。
Fog of War · 战雾
Not yet specified = 范围内但不清晰。测试:能问清问题吗?不能 → fog。
Out of Scope ≠ Fog
范围外 vs 不清晰,两件不同的事。各自有独立区域。
HITL vs AFK
Ticket 类型分两种模式。HITL = 人在环,AFK = 模型独走。伦理边界:模型不代人那方。
Native Tracker Blocking
用 tracker native 依赖关系,不在 body 里写 convention。UI 视觉化 frontier。
Claim = Assignee
Ticket 的 assignee 就是 claim。未分配的 ticket = 未声明。first-write 就 assign。
Refer by Name
不用 #42,用 ticket title。id 嵌名字里,不替代名字。
One Ticket Per Session
每 session 一个 ticket(research 例外)。smart zone 限制的具体应用。
Destination First
制图先定 destination。它锁定 scope,所有 ticket 都向它对齐。

11 启发 · 我们可以抄什么?

★ 给巨型项目治理的启示

1. Plan Don't Do:产出决策不产出交付物。模型定位要清晰。
2. Map as Index:map 不存内容,只索引 + 链接。决策只存一处。
3. Fog vs Out of Scope:战雾是"清晰但还没做",out-of-scope 是"做了但不在范围"。
4. HITL 边界:模型不代人那方,伦理清楚。
5. Native UI as Truth:用 tracker 的原生依赖,让 UI 视觉化 frontier。
6. Claim = Assignee:未分配 = 未声明,first-write 即 claim。
7. Name > ID:用名字,id 嵌名字里。
8. One Per Session:smart zone 限制的具体应用。
9. Destination First:制图先定目的地,锁 scope。
