02 Root Virtue · 可预测性

SKILL.md §7:"A skill exists to wrangle determinism out of a stochastic system. Predictability — the agent taking the same process every run, not producing the same output — is the root virtue; every lever below serves it."
★ Predictability ≠ Same Output

可预测不等于同样输出。可预测 = 同样的过程,但输出随上下文合理变化。
LLM 是随机系统,skill 的存在是为了约束这个随机性到可预测的过程。

03 两种 Invocation · Context vs Cognitive

⚙️ Model-Invoked
Cost: Context Load · description 每轮都在窗口里
omit disable-model-invocation · 写 model-facing description · 触发短语丰富
👤 User-Invoked
Cost: Cognitive Load · 你要记住它存在
disable-model-invocation: true · description 变 human-facing 一行摘要
§20:"When user-invoked skills multiply past what you can remember, that piled-up cognitive load is cured by a router skill: one user-invoked skill that names the others and when to reach for each."
这正是 ask-matt 的存在原因!

04 Description 写作 · 3 条原则

SKILL.md §26–28 行:

  1. Front-load leading word —— description 前置技能的核心词
  2. One trigger per branch —— 同义 branch 是重复,合并
  3. Cut identity already in body —— description 只保留 triggers + "其他 skill 需要时"
★ Description 比 body 还严

"Every word increases context load, so a description earns even harder pruning than the body"
Description 每轮都占 token,所以比 body 更要狠心修剪。

05 信息层级 · 3 层阶梯

1
In-skill step · SKILL.md 主层
有序动作 · agent 做什么,顺序。每步以 completion criterion 结尾 —— 可检查,可能穷举。
模糊 criterion → premature completion(没做完就当做完)。
2
In-skill reference · SKILL.md 内参考
定义、规则、事实 · 按需查阅。合法 flat peer-set(同一层多规则),不是设计问题。本技能就全是 reference。
3
External reference · 外部参考
推出 SKILL.md 到单独文件 · context pointer 触发时加载。
跨度:从 sibling 文件(GLOSSARY.md)到完全外部资源。
Progressive Disclosure · 渐进披露:
把内容沿阶梯往下推,让顶层保持可读。
branching 是干净的披露测试 —— 每条 branch 需要的 inline,只有部分需要的走 pointer。

06 何时拆分 · 2 种 cut

拆分方式何时代价
By invocation 有 distinct leading word 应自主触发 / 其他 skill 要 reach 新 description 占 context
By sequence 后续步骤诱惑 agent 跳过当前步骤(premature completion) 藏起来让 agent 专注当前

07 Leading Words · Pretraining 词的力量

Leading word = 模型预训练里已经存在的紧凑概念。
在文本里反复出现 → 累积定义 → 用最少 token 锚定整块行为。

"fast, deterministic, low-overhead" → tight 一个 pretraining 词(tight loop)替代多个描述
"a loop you believe in" → red 把模糊的"我相信"换成可观察的二元状态(红 / 绿)
"be thorough" → relentless weak leading word → stronger word,not different technique

§72:"Assume every skill is carrying restatements that leading words retire — go find them."

★ 双赢

§72:"You win twice over: fewer tokens, and a sharper hook for the agent to hang its thinking on."
Leading word 不只省 token,还让模型在描述里看到同一词时更可靠触发。
当 word 出现在 prompt / docs / code / description 里 —— 模型建立强关联。

08 6 种 Failure Modes

Premature Completion
步骤没真做完就当做完。注意滑到"being done"。
防御: 锐化 completion criterion → 必要时按 sequence 拆分。
Duplication
同义多处出现。维护成本 + token + 在层级上虚高。
防御: Single source of truth。
Sediment
陈旧层因"加安全删危险"沉淀下来。
防御: Pruning discipline。
Sprawl
即使每行都活且 unique,也太长。
防御: 阶梯 + 按 branch / sequence 拆分。
No-op
说了句模型默认就遵守的。等于花钱说废话。
测试: 它改变默认行为了吗?
Negation
"别想大象"反而命名大象,让它更可达。
防御: 说做什么,不说不做什么。

09 Pruning · 修剪纪律

SKILL.md §55–59 行给出 3 条:

  • Single source of truth · 一个权威地点,改一处即可
  • 每行检查 relevance · 还和技能做的事相关吗
  • 整句删除 no-ops · 不是删字,是删整句。"Most prose that fails should go, not be rewritten."
设计哲学:pruning 不只是删冗余 —— 它是"默认失败的命运"。
§81:"The default fate of any skill without a pruning discipline."
没有修剪纪律的技能 = 注定膨胀。

10 关键设计模式

Predictability as Root Virtue
"Predictability = same process, not same output"。所有 lever 都服务它。
Context vs Cognitive Load
两种 invocation 的核心 trade-off。Model-invoked 付 context,user-invoked 付 cognitive。
Description Harder Pruning
Description 每轮占 token,比 body 更要狠修剪。
Information Hierarchy · 3 层
In-skill step > In-skill reference > External reference。push too little / too much 是核心 tension。
Progressive Disclosure
沿阶梯往下推。Branch 决定 inline vs pointer。
Completion Criterion · 可检查
每步以 completion criterion 结尾。可检查 + 可能穷举。模糊 = premature completion 邀请。
Leading Word as Token
一个 pretraining 词替代多个描述。省 token + 增强 trigger 关联性。
6 Failure Modes as Diagnostic
6 种失败模式作为诊断工具。每个有防御措施。
Negation Backfires
禁止某物反而命名它。说做什么,不说不做什么。

11 启发 · 我们可以抄什么?

★ 给 Skill 作者的终极启示

1. Predictability 是 root virtue:same process, not same output。
2. 两 load 必择一:context load(model-invoked)或 cognitive load(user-invoked)。
3. Description 修剪 > body:每轮占 token。
4. 3 层阶梯:step > reference > external,branch 决定 inline/pointer。
5. Completion Criterion 可检查:模糊 = premature completion 邀请。
6. Leading word 替代多个描述:pretraining 词 = 双赢(省 token + 强 trigger)。
7. 6 Failure Modes:每个有防御,可作为诊断工具。
8. Sediment 是默认命运:没 pruning 必膨胀。
9. Negation 反向:说做什么,不说不做什么。
10. Router 解认知负担:user-invoked 太多 → 写一个 router(如 ask-matt)。
