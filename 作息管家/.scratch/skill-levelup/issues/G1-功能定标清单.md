# G1 功能定标清单（2026-08-09 定稿 · 人类 Q1-Q12 全采纳）

> 本清单 = G1 票的决议主体，是 G2 场景枚举的直接输入。
> 每场景含：呈现数据 / 交互形态 / 命令 / 模板 / 新场景注册。

---

## A. 重点深度（6 场景）

### A1 记录（record）
- **呈现数据**：三件套——全天作息时间轴 + 过去几小时推断高亮 + 当前状态总览（笔数/覆盖时长/缺口时段）
- **交互形态**：自适应（信息全→一步直达；缺→过程页补）
- **命令**：`add` 后联动渲染结果 HTML（新链路）或新命令
- **模板**：记录结果 HTML（作息表形态，高中作息表升级版）
- **新场景**：注册「记录」

### A2 复盘今日（cross-domain）
- **呈现数据**：计划 vs 实际对照 + 4 段叙事 + 单日健康分 + 异常/缺口/反常
- **交互形态**：多轮（缺计划 → 提示补齐引导，不降级）
- **命令**：`render-replay` 强化（对齐"今晚复盘"体验）+ 异常并入
- **模板**：今日复盘 HTML
- **新场景**：注册「复盘今日」

### A3 复盘本周
- **呈现数据**：7 维趋势 + 热力图 + 健康分均值趋势（含异常日标注）+ 本周亮点/问题 + 异常/缺口
- **交互形态**：一步直达
- **命令**：周粒度聚合 + 渲染（新/强化）
- **模板**：周复盘 HTML
- **新场景**：注册「复盘本周」

### A4 复盘本月
- **呈现数据**：月度聚合 + 环比对比 + 目标达成 + 健康分趋势（含异常日标注）+ 异常/缺口
- **交互形态**：一步直达
- **命令**：月粒度聚合 + 渲染（`render-record-compare-months` 强化）
- **模板**：月复盘 HTML
- **新场景**：注册「复盘本月」

### A5 制定次日计划（plan）
- **呈现数据**：时间轴 + 分类色带 + 与历史作息贴合提示
- **交互形态**：多轮（商量计划强化：生成 → 调整 → 再生成）
- **命令**：`upsert-plan` / `ensure-plan-event` 现有 + 渲染强化
- **模板**：计划结果 HTML
- **新场景**：注册「制定计划」（强化既有商量计划）

### A6 周视图（广度 · record）
- **呈现数据**：7×24 一周作息总览（网格/热力图）
- **交互形态**：一步直达
- **命令**：周视图渲染（新）
- **模板**：周视图 HTML
- **新场景**：注册「周视图」

## B. 基础覆盖（5 项 · 不新增场景或沿用现有）

| 项 | 现状 | 处理 |
|---|---|---|
| 查询 / 时间线 | `list`/`timeline`/`report` 等现有 | 保留场景，跟随 L 级视觉统一 |
| 分类管理 | `list-categories`/`propose-category`/`approve-category` 现有 | 保留 |
| 飞书同步 | `feishu-resync` 现有 | 保留 |
| 批量导入 | batch-add（R2 已设计） | 实施阶段补命令 |
| 异常 | 并入 A2-A4 复盘 | 不独立场景 |

## C. 跨场景约定

- **复盘 → 计划衔接**：复盘结果 HTML 底部给「去制定明日计划」复制 prompt 引导（A2-A4 模板含）
- **缺数据兜底**：对照类场景缺计划 → 提示补齐引导，不降级、不自动造值
- **健康分**：全粒度（今日单日 / 周月均值+趋势+异常日标注）
- **场景名**：注册进 scenarios.yaml 的场景名 = 上表「注册」列，不口语化、无变体
- **呈现原则**：数据全面 → 图表/图形全力呈现；每场景独立脚本 + HTML（复用仅必要时）
- **daily_summary**：本清单未依赖；若 G2 场景需要聚合呈现可评估复用（待评估资产）

- 新注册场景：记录 / 复盘今日 / 复盘本周 / 复盘本月 / 制定计划（强化）/ 周视图 → 场景数 73 → 79
- 现有场景核对与 L 级视觉统一在 G2 完成
