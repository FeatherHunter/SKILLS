## Question

在**交互铁律 v2** 约束下，领域第一的**深度功能**做哪些？**广度功能**挑哪几个？各自做到什么程度、**呈现哪些数据**、对应哪些新场景？

## 背景

- R1 竞品对标（勿重查）：差异化空白 = 「作息记录(回顾)+日程计划(前瞻)+AI 复盘闭环」四家全空缺；作息管家独有：商量计划 / 复盘 start-end / 健康分 / 7 维趋势 / 24h 热力图 / 5 状态 fallback / 飞书日历双向联动
- 用户拍板（Q11）：**深度+广度都做**，全部在「HTML + 复制 prompt」交互闭环内成立

### 顶层体验输入（2026-08-08 用户口述 · 最高优先级，详见 `.scratch/skill-levelup/specs/顶层体验描述-2026-08-08.md`）

1. **每晚工作流 = 重点**：每天晚上「复盘（今天/本周/本月）」+「制定第二天计划」。这两个功能的 HTML 数据呈现 + 工作流程设计，花最大力气做好（不代表其他功能不重要）
2. **记录结果型 HTML**：记录每一笔之后返回结果型 HTML——看到过去几小时推断了什么 + 整天到目前为止的作息表；高中作息表形态但要漂亮、信息明显；从用户角度用图表/图形让信息全面
3. **场景 = 独立呈现单元**：无「变体」概念；每个场景独立信息、独立呈现设计，争取独立脚本 + HTML 页面（复用仅必要时）
4. **场景名不口语化**：场景名 = 展示清单里的词，用户只说看到的词
5. **daily_summary**：旧设计，价值待本票/场景规划评估（不预设废弃）

### 三层评估结论（2026-08-08 · 详见 `.scratch/skill-levelup/specs/`）

- **DB 层**：schedule_records 3252 条/91 天、schedule_plans 1081 条/72 天、daily_summary 452 行（停更 7-02）、legacy 21 天；plans 日期混格式脏数据（`20260613`）；分类分布极不均（工作 69%）
- **CLI 层**：49 命令读写+渲染齐全；**缺口**：①记录后即时结果型 HTML 链路 ②复盘工作流强化（现有 render-replay 是 start-end）③batch-add（R2 已设计）
- 场景覆盖层：本票 + G2 定

## 已定决策（第一批 · 2026-08-09 人类采纳，详见 `.scratch/skill-levelup/issues/G1-决议-第一批.md`）

| # | 决策 | 结果 |
|---|---|---|
| Q1 | 记录结果型 HTML 呈现范围 | A 核心三件套：时间轴 + 过去几小时推断高亮 + 当前状态总览（不叠分类统计/计划对照） |
| Q2 | 复盘粒度深度 | A 分层：今日=对照+4段叙事+健康分；周=7维趋势+热力图+亮点/问题；月=聚合+环比+目标达成 |
| Q3 | 制定次日计划方向 | C 呈现优先（时间轴+分类色带+历史贴合提示），交互流程后打磨 |
| Q4 | 广度功能 | A 周视图进 L 级；NLP 日期解析不做 |

## 约束

- **交互铁律 v2**：① 一步直达（无过程页）② 多轮过程（过程 HTML → 操作 → 复制 prompt 继续）③ 多轮变种；不引入第三种交互范式
- 不补"竞品已有但需脱离闭环才能做"的功能

## 交付

功能定标清单：深度 N 项 + 广度 M 项，每项含：**呈现的数据** / 交互形态（一步直达 or 多轮）/ 新场景 / 新模板 / 新命令。决议评论挂本票，**blocking G2 场景枚举**。
