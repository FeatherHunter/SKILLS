## 2. 封装充分性结论

- ✅ **record 域**：读写 + 10 渲染命令，覆盖充分
- ✅ **plan 域**：读写 + 4 渲染命令，覆盖充分（ensure-plan-event 幂等语义）
- ✅ **复盘**：render-replay（start-end）+ 对比命令已存在
- ⚠️ **记录 → 结果型 HTML 链路缺失**：`add` 是单条写入，**没有"记录一笔后立即返回结果型作息表 HTML"的链路**（用户核心需求，见顶层体验描述 §5）——需新增或改造
- ⚠️ **batch-add 缺失**：R2 已设计（收敛进 CLI），实施阶段补
- ℹ️ **daily_summary**：`add-summary` 写 / summary 读存在，但表停更（待评估资产，见顶层体验描述 §7）

## 3. 缺口清单（第 3 层场景设计时验证）

1. 记录后即时结果型 HTML（顶层体验 §5）——需要 add 后联动渲染或新命令
2. 复盘（今天/周/月）工作流的专用命令强化——现有 render-replay 是 start-end，需对齐"今晚复盘"体验
3. batch-add（R2 已设计）

## 4. 对第 3 层的指引

场景设计时：能直接复用现有命令 → 纯前端/流程设计；能力缺失 → 进入"缺哪个补哪个"通道（动 DB 需用户确认）。
