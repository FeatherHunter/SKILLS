## 决策记录(2026-08-02 · 本轮用户拍板)

1. **多标签模型 = 字符串编码**(逗号分隔,如 `正面,侧面`;单个标签 ≤ 20 字,单张 ≤ 10 个)
   —— 0 schema 变更,研究报告 §2.6 方案 2
2. **删空语义 = 至少保留 1 个标签**(删空报错拒绝;想清空全部用「改照片标签」)
   —— 与既有硬规则「tag 必填」一致
3. **手机发图双模式**(P0 · 用户指出):发图模式(手机/飞书,图片与文字分离到达)+ 路径模式(电脑);
   「同一轮对话内用户发的所有图片 = 本次要存的照片」;缺标签逐张追问(规则已落地 SKILL.md)
4. **看身材照时间三表达**:天数(如最近 30 天)/ 某个日期 / 一段范围;未填默认最近 90 天;
   底层 CLI 归一为 `--start/--end`(单日 = start=end;`--days N` 自动换算)
5. **对抗式审查 7 项处置**(C1-C7):C1 双模式(见 3)/ C2 时间参数(见 4)/ C3 GIF 帧数回传
   (`generate_gif` 挂 `_last_gif_info`,result 页呈现)/ C4 加标签支持多标签(逗号分隔逐个追加判重)/
   C5 删除知情提示(物理删不可恢复)/ C6 删空出路提示(引导改照片标签)/ C7 对比选图方式明确(日期/编号/候选)

## 格式约定(2026-08-02 讨论沉淀)

1. 存照片类 prompt 不假设「路径」,双模式(发图/路径);标签缺省追问
2. 时间参数一律让用户填(天数/单日/范围),AI 翻译成 CLI 参数
3. 「完成后给 1 句话总结」并入 body 段,不放最后
4. 物理删除场景带知情提示;删空/判重等边界在 prompt 里给出路
