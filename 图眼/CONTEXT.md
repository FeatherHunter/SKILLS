# 图眼 · 领域上下文

## 一句话

「图眼」= 图片 → 高保真文本的细节保真管线，给无视觉模型（deepseek-v4-flash 等）当眼睛。

## 为什么存在

- deepseek-v4-flash 等纯文本模型推理强、成本低（个人免费），但没有视觉模态。
- 单次「看图→文字」是有损压缩：小字/角落/细节会被牺牲或幻觉（实测把便签念错）。
- 图眼把「看一次」升级为「看四层」：全景 + 切片放大 + 专项 OCR + 审问循环，信息量约 10 倍。

## 核心概念

| 概念 | 含义 |
|---|---|
| 眼睛 | mmx vision describe（MiniMax VLM），单次看图转文本 |
| 调用者 | 使用本技能的 agent（如 deepseek-v4-flash 通过 /图眼 调用）——自己就是大脑 |
| 兜底大脑 | MiniMax-M3（仅 ask/audit 子命令内置，供无大脑的纯 CLI 环境） |
| 粗看 look | 1 次整体描述，快速问答用 |
| 精扫 scan | 3×3 切片+12% 重叠+放大 1024px+逐片审计，10 次调用，细节主力 |
| 读图 ocr | 专项 OCR 提取全部文字 |
| 问图 ask | 精扫文档 + 问题 → 兜底大脑推理（无大脑环境用） |
| 审图 audit | 兜底大脑审问→眼睛定向答，多轮收敛（无大脑环境用） |

> v1.1 架构修正:图眼是纯眼睛,不内置推理大脑、不集成任何推理模型 API。
> 调用者(deepseek 等)拿到文本自己推理——不存在 API key 的说法。

## 架构要点

- 5 层骨架：无数据层（无 DB/无持久状态，临时文件走 tempfile）；操作层=eye.py；规则层=references/prompts.md（软规则）；接口层=argparse + `{status, data, message}`；文档层=SKILL.md + HELP HTML
- 长文本大脑调用强制走 `--messages-file`（Windows 命令行长度限制）
- 中文路径/参数全部列表传参（反模式 7）

## 边界

- 不生成图片（→ mmx-cli / 智剪工坊）；不处理图片（→ 智剪工坊）
- 手写体/模糊小字 VLM 可能读错——大脑如实标注，不硬译
