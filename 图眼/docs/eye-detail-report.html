如何让 deepseek
看到图片的每一个细节

单次「看图→文字」是有损压缩。要逼近「看到每一个细节」，需要一套多尺度、多轮次的细节保真管线——本报告含真机对比实验。

Mavis · 2026-08-11 · 真机实测（1024×1024 细节密集场景，10 次 vision 调用）

一、先认清物理现实：单次看图是「有损压缩」

一张 1024×1024 图 = 约 100 万像素；一次 VLM 描述 = 最多几百到一千 token。中间横着一道信息瓶颈——模型只能挑「它觉得重要」的内容说，于是：

  • 角落细节丢失：小字、小物体、边缘内容最先被牺牲；
  • 文字被幻觉：看不清的小字会被「脑补」，实测基线把便签念成 "Easy milk / Rare rise"（错误）；
  • 无坐标、无结构：只说「有本书」，不说在哪、什么颜色、几本。
💡 目标校准：文本通道物理上无法做到 100% 无损。工程目标是「逼近完备」——用多轮、多尺度、结构化、审问收敛，把信息损失压到工程上可接受。

二、真机对比：粗看 vs 精扫

同一张细节密集桌面图（书籍小字 / 便签手写 / 计算器数字 / 硬币 / 价格标签），两种喂法：

方案 A · 单次整体描述（粗看）
~1.5K
1 次调用 · 输出字符
整体结构清楚，但便签文字多处读错，无数值/坐标精度，小物体（核桃、USB 线）完全没提。
方案 B · 切片精扫（3×3 + 放大）
~15.4K
10 次调用 · 输出字符
信息量约 10 倍，新增小物体、精确到按键的文字、硬币分类计数、位置坐标，并纠正了粗看的幻觉。
原图按 3×3 网格切分（红网格线 + 编号），每片放大到 1024px 后独立审计

精扫「看见」了粗看漏掉的东西

新增发现桌上有 碎核桃（切片 2-2，粗看完全没提）
新增发现计算器屏幕精确数字 345,892、键盘 P1–P4 功能键（粗看未提）
新增发现硬币按面值分类计数：Quarter ×3-4 / Dime ×2 / Penny ×1-2（粗看只说「几枚硬币」）
新增发现白色 USB 充电线、撕碎的笔记本纸（红蓝线条+螺旋装订孔）、iPhone（带 Home 键）
新增发现价格标签细节：红色加固孔 + 白色棉绳（粗看只读出 $12.99）
纠正幻觉粗看把便签念成 "Easy milk / Rare rise"（无意义）；精扫读为 "Potential ideas / Review to the next part due Friday / Call Sarah / Buy milk"
位置信息每片描述自带方位词（左上/正中/右下），组合后可还原 物体空间分布图

数据来源：基线 1 次调用（detail-scene.png）vs 切片 9 次调用（scan/tile_*.txt），均走 mmx vision describe --output json，中文审计 prompt。

三、细节保真管线：四层递进

把「看一次」升级为「看四层」，每层补上一层丢的信息：

L1 全景层整体结构 / 大物体 / 空间关系
1 次调用
→
L2 切片层3×3 切分 + 放大 + 逐片审计
9 次调用 · 细节主力
→
L3 专项层OCR 全文 / 数值提取 / 颜色材质
按需 1-3 次
→
L4 审问层deepseek 读合并文档 → 生成追问清单
→ 局部再查 → 循环收敛

L1 全景层

mmx vision describe --image photo.png --prompt "描述整体场景、主要物体及其空间关系,按左上→右下扫描顺序,列出结构" --output json --quiet

L2 切片层（细节主力）

Python（PIL）把图切成 3×3 带 12% 重叠的切片，每片放大到 1024px 后独立调用：

# 关键参数(实测): 3×3 网格 + 12% 重叠(防物体被切边) + LANCZOS 放大 2.4×
# 每片审计 prompt(强制"宁多勿漏"):
#   你是高精度图像审计员。逐项列出:1)所有物体及位置(左/中/右/上/下)
#   2)所有文字逐字输出,一个标点都不要漏 3)数字/价格/日期精确数值
#   4)颜色材质细节。宁可误报不可漏报。

L3 专项层（按需）

对关键区域追加专项抽取：OCR 全文、计算器读数、发票金额等。

L4 审问层（deepseek 反客为主）

把前三层文档全部塞进 deepseek-v4-flash（1M 上下文完全接得住），然后让它「审问」：

# 伪代码: 审问循环
doc = merge(L1, L2, L3)              # 合并细节文档
while not deepseek.satisfied(doc):
    question = deepseek.ask("还想确认哪些区域/细节?")   # 生成追问清单
    answers = mmx.vision_describe(doc["regions"], question)  # 眼睛定向回答
    doc = merge(doc, answers)        # 文档增量更新, 循环直至收敛

这一层把「无视觉模型」变成了「主动审问者」——它最清楚自己缺什么信息，眼睛只负责按它的问题精确取景。

四、六个工程要点（实测经验）

要点为什么
切片要重叠 10-15%物体正好卡在切缝上会两片都看不全（实测杯子文字被切开）
切片要放大再送小字在原分辨率下 VLM 看不清，放大 2× 以上显著提升 OCR 准确率
多视角 prompt 各司其职「审计式」prompt 比「描述式」多挖 3-5 倍细节；OCR/数值用专项 prompt
要位置不要散文强制「物体+方位」格式，拼回后能重建空间分布；散文描述不可定位
深色大图用 JPEG 内嵌报告/文档内嵌图时 JPEG 体积远小于 PNG（264KB vs 700KB+）
审问循环控制轮次建议最多 2-3 轮，每轮限 3-5 个追问，避免成本失控

五、成本账（要不要这么奢侈？）

方案vision 调用适用场景
粗看（1 次）1日常问答、图片分类、快速理解——大部分场景够用
标准精扫（L1+L2）10截图审计、UI 还原、文档 OCR、发票核对——推荐默认
深度精扫（L1-L4）12-15医学影像、文物细节、图纸复核、证据保全——信息价值 > 成本

判断准则：信息价值 × 误读代价 > 10 次 vision 调用成本，就上精扫。deepseek 侧免费 + 1M 上下文，成本全部来自眼睛。
