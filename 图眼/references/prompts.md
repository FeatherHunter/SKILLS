# 图眼 · Prompt 模板库与场景分级

> 软规则参考:不是硬编码清单,是给 AI 的「心法 + 模板」。场景分级帮 AI 决定该用粗看还是精扫。

## 一、场景分级:什么时候用哪档

判断准则(用户可覆盖):
**信息价值 × 误读代价 > N 次 vision 调用成本 → 上更高档。**

| 档位 | 调用次数 | 适用场景 | 命令 |
|---|---|---|---|
| 粗看 | 1 | 日常问答、图片分类、快速理解 | `look` |
| 标准精扫 | 10 | 截图审计、UI 还原、文档 OCR、发票核对、便签/手写 | `scan` / `ask --mode scan` |
| 深度精扫 | 12-15 | 医学影像、文物细节、图纸复核、证据保全、模糊小字 | `audit --rounds 2-3` |

典型判断:
- 用户只是「这是什么」→ 粗看
- 用户要「图里写了什么/有什么细节」→ 标准精扫
- 用户说「帮我仔细看看/核对/审计」→ 深度精扫(审问循环)

## 二、Prompt 模板库

### 2.1 全景 prompt(look 默认 / L1)
```
详细描述这张图片,列出所有物体和所有文字。
```

### 2.2 结构扫描 prompt(L1 全景层用)
```
描述整体场景、所有主要物体及其空间关系,按左上→右下扫描顺序。
```

### 2.3 审计 prompt(切片层核心,eye.py 内置 AUDIT_PROMPT)
```
你是高精度图像审计员。这是原图放大后的局部区域。请逐项列出:
1) 所有物体及其大致位置(左/中/右/上/下);
2) 图中出现的所有文字,逐字输出,一个标点都不要漏;
3) 数字、价格、日期等精确数值;
4) 颜色、材质等视觉细节。宁多勿漏,宁可误报不可漏报。
```

### 2.4 OCR prompt(eye.py 内置 OCR_PROMPT)
```
请提取这张图片里的所有文字内容,逐字输出,保留原文格式,
不要翻译、不要解释、不要添加任何内容。
```

### 2.5 局部追问 prompt(审问循环用)
```
针对这个局部区域回答:
<问题>
只输出与该问题相关的细节,精确具体。
```

### 2.6 大脑侧审问者 prompt(audit 用)
```
这是一张图片的多区域细节描述文档:
<文档>

你现在扮演审问者,找出信息最不足的区域。请输出 N 条追问,
每条格式: 区域名(全景 / 上左区 / 上中区 / 上右区 / 中左区 / 中中区 /
中右区 / 下左区 / 下中区 / 下右区)|具体问题。
不要问文档里已有答案的问题。
```

### 2.7 大脑侧回答 prompt(ask 用)
```
以下是一张图片的描述:
<细节文档>

用户的问题:<问题>

请基于描述给出准确回答。若描述信息不足,明确说明缺什么,不要编造。
```

## 三、心法(软规则,非关键词表)

1. **逼细节,不逼概括**:审计类 prompt 让 VLM「报清单」而不是「写总结」——清单式输出信息密度高 3-5 倍。
2. **位置 > 散文**:强制「物体+方位」格式。散文描述不可定位,无法支撑审问循环。
3. **宁可误报不可漏报**:漏报是信息损失,误报可由大脑二次推理过滤。
4. **大脑要诚实**:让大脑明确说「信息不足,缺什么」,禁止编造。这是防止「无视觉模型幻觉看图结果」的关键。
5. **切片重叠是刚需**:物体卡在切缝会两片都看不全。默认 12%,密集小字场景可提到 20%。
6. **文字类任务先 OCR 后审计**:发票/截图/便签,OCR 专项 prompt 的识字精度高于通用描述。

## 四、已知边界

- 手写体、模糊小字、被遮挡文字:VLM 会尽力但可能读错——大脑侧要如实标注置信度,不硬译。
- 大图(>4K)建议先等比缩到 2048 再精扫,否则切片数量爆炸、成本失控。
- 审问轮数建议 ≤3,每轮 ≤5 条追问,超了就是场景选错档。
