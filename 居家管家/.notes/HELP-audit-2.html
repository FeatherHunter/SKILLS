原因:scenarios.yaml 里第一个 scenario 是 修物品(不是按用户视角的"高频 → 低频"排序)。Python setdefault 保留插入序,所以 build_help_payload 把 "修物品" 当成第一个 group。

用户看到的第一屏:修物品 → 借物品 → 减物品(都是更新类子项)。而用户最常用是 查物品 / 看物品 / 录物品。违反总纲 03 §高频优先。

修复:scenarios.yaml 按用户视角重排(查询类 → 录入类 → 更新类 → 统计类 → 账号 → 元数据),或 help_center.py 显式排序 sorted(grouped.items(), key=lambda x: ORDER.index(x[0]) if x[0] in ORDER else 99)。

BUG 9 · 复制按钮在 fallback 路径下会复制"undefined"P0

实测(代码审查):

function copyText(btn, text) {
  if (navigator.clipboard?.writeText) {
    navigator.clipboard.writeText(text).catch(() => fallbackCopy(text));
  } else {
    fallbackCopy(text);
  }
}

function fallbackCopy(text) {
  const ta = document.createElement('textarea');
  ta.value = text;        ← 若 text=undefined, ta.value = "undefined"
  document.body.appendChild(ta);
  ...
}

原因:如果 `text` 是 `undefined`(s.find() 返回 null),`ta.value = undefined` → 浏览器字符串化为 "undefined" → 用户复制到粘贴板看到 "undefined"。

当前触发条件:用户的 button data-sid 和 payload group index 不匹配(例如重构 group 顺序后没更新按钮)。当前 scenes.yaml 内 sid 唯一所以不会触发。

修复:copyText(btn, text || '');或加 if (!text) { alert('场景数据缺失'); return; }。
