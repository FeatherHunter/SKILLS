HELP 同步 · 现在 2 个不自动的环节

你问的本质

代码行为:build_manual.py 会用 shutil.copy2 把 HELP HTML 写到 SKILL/居家管家.html。

触发方式:手动跑 python3 scripts/build_manual.py。没有自动化。

2 个不自动的环节

① 跑 build_manual 这步不自动

现状:你改了 references/scenarios.yaml 后,必须记得手动跑: 
python3 scripts/build_manual.py
不跑 → 居家管家.html 不会更新 → 镜像脱钩。

可加固方案(三种任选)

方案 A · pre-commit 钩子触发(推荐)

在 SKILLS/.githooks/pre-commit 里,如果 diff 含 居家管家/references/scenarios.yaml 或 templates/help_center.html,自动跑 build_manual.py,把更新后的 居家管家.html 一起进 commit。

# pre-commit 新增
if echo "$CHANGED" | grep -qE '居家管家/(references/scenarios|templates/help_center)\.'; then
    cd 居家管家 && python3 scripts/build_manual.py
    git add 居家管家.html
fi

好处:你改 yaml / template 时,commit 自动带上新 HTML,零额外动作。

方案 B · Makefile 强约束

SKILL 目录加 Makefile:

sync-html:
\tpython3 scripts/build_manual.py

test: sync-html
\tpython3 -m pytest tests/ -q

precommit: sync-html
\tpython3 -m pytest tests/

你 commit 前跑 make precommit 一气完成。

方案 C · GitHub Action / CI

不适合本地 SKILLS 仓库(你已决定不做 web CI)。

② test_manual_sync 报警不阻断

现状:tests/test_manual_sync.py 用 pytest assertion 检测居家管家.html 与 HELP HTML 不一致 → 抛 AssertionError → pre-commit 钩子 exit 1 → 阻止 commit。

但实测它能拦住 commit 只有当你跑了 pytest 之后才生效(pre-commit 钩子跑 pytest)。

实测: 
# 场景 1: 你改了 scenarios.yaml 但没跑 build_manual,直接 git commit
$ git commit -m "改 yaml"
  🧪 [pre-commit] 跑 居家管家 pytest
  ❌ 居家管家 同步断言失败
  阻止 commit  ✓ (这步你已经被拦住)

# 场景 2: 你跑 build_manual 后 git commit
$ python3 scripts/build_manual.py
  ✓ 居家管家.html 已与 HELP HTML 同步
$ git commit -m "改 yaml"
  🧪 [pre-commit] 跑 居家管家 pytest
  ✓ [居家管家] 测试通过
  commit 成功  ✓

我的推荐

方案 A(pre-commit 钩子触发 build_manual) + 已有 test_manual_sync 阻断。
两者结合 = 改 yaml/template 就能 commit,无任何手动步骤,镜像自动同步且测试断言。

  • 当前够用:只靠 test 阻断,改 yaml 后必须手动跑 build_manual 才能 commit
  • 都不要:现状,改 yaml/template 后自己记得
