# 复制按钮契约 v2(按钮文字恒定 + prompt 自包含 + 参数化表单)

> 来源:审查 ISSUE #123(2026-08-10 对抗式审查拍板)· 跨技能适用 · 决策权威记录见 ISSUE #123 评论。
> 本 ADR = 设计思想留档(供任何 Agent 接手时理解"为什么"),决策本体 = GitHub Issue(跨工具可读)。

## 背景

对抗式审查发现:全技能 HTML 的复制按钮点击后把自身文字替换为「✓ 已复制」(flashBtn 反模式),违反第一性原理——**按钮文字是功能标签(永久身份),瞬时状态不得改写标签**。问题辐射:居家管家 306 模板 + 卡路里 293 + 饼干记账 51 + 08 规范骨架 `template_skeleton.html` 自身同款。

同时发现复制 prompt 的两个深层问题:
1. **不自包含**:prompt 缺技能路由/缺唤醒词,空白 session 的 AI 拿到不知加载什么、执行什么(例:「我想录第一批物品…」→ 用户口吻,AI 误认为闲聊)
2. **参数不可定制**:关键参数(路径/份数/格式)由 AI 渲染时写死,用户只能整段复制,无法在复制前表达「我想改这里」

## 决策

### 决策 1:复制按钮文字恒定
点击后按钮文字**不允许改变**、**不允许出现「已复制」**;反馈走独立 Toast(居家管家「知道了」面板样式,与 help_center 同款:暗色毛玻璃 + 图标 + 标题 + 详情 + 关闭按钮)。

### 决策 2:复制 prompt 必须自包含
空白 AI 拿到即可执行,格式:
```
请加载「XX」技能,帮我<动作>(唤醒词:<词>):<参数>
```
禁止用户口吻、禁止裸参数。参照 08 规范「4 部分 prompt 模板」(场景/数据/期望/来源)。

### 决策 3:复制 prompt 参数化(采集型表单)
关键参数用可编辑字段(input/select),预填真实值,下方实时预览完整 prompt,空值点击拦截提示。
- 依据:08 规范「采集型 = 字段表单(预填度 0→100% 连续;全预填 = 样式只读但可修改)」
- 参数(路径/保留份数/导出格式/冲突处理)→ 表单;场景语义(唤醒词/动作)→ 模板固定
- 复制数据/复制日志 = 纯数据(5 段 JSON / 6 段日志),不进表单(存档/排障用途)

### 决策 4:首次使用类 HTML 渲染 env 状态 + 真实路径
- 渲染环境变量状态卡片(SKILLS_DB_PATH / HOME_PHOTOS_DIR 当前值或「未设置,走默认」)
- env 未设置时提供「先配置环境变量」引导按钮(复制自包含配置 prompt)
- db_path 从环境变量运行时推导,禁止写死 fallback 假路径
