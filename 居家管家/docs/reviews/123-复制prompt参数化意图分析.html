复制 prompt 参数化 · 第一性原理

你要的是「决策型 prompt」——复制前可定制,复制后即执行

从「固定文本快照」升级为「字段表单」:参数可编辑,复制出去的是用户定稿版指令

1你的意图是什么

当前这几个 HTML 的复制按钮,复制的是一段固定文本——参数(路径/份数/格式等)由 AI 在渲染时写死,用户只能「整段复制」,无法表达「我想改这里」。

你要的本质上是一个决策点:用户在复制前,有权利对关键参数做最后定制。这正是 08-HTML 交互规范「采集型」的定义——

采集型 = 字段表单(预填度 0→100% 连续;全预填 = 样式只读但可修改) —— 录入/记一笔/记一餐的形态。预填 = AI 智能默认;可改 = 用户主权。

一句话:复制按钮从「复制一段话」变成「复制一份用户签过字的表单」。

2规则:什么样的参数进表单

  • 有默认值的可变参数 → 表单字段(如路径/保留份数/导出格式)
  • 场景固定的语义 → 留在模板里(如「唤醒词:首次使用」「建库含分类种子 60 节点」)
  • 选择型 → select/radio(如 备份 vs 导出、JSON vs CSV)
  • 自由输入 → input(如自定义路径、备注)
  • 预填度 100%:字段默认显示当前真实值,用户不改直接复制 = 现在的行为;改了 = 定制版
  • 空值处理:必填参数为空时,复制按钮提示「请填写 XX」,不复制残缺指令

4实现方式

  • 模板 JS:参数区域从「字符串拼接」改为「<input>/<select> 绑定 oninput → 实时重算 prompt 预览」
  • 按钮点击 → 读取当前表单值 → 拼接自包含 prompt(技能路由 + 唤醒词 + 参数)→ 复制 → 面板 Toast 确认
  • 「实时预览」:表单下方显示拼接后的完整 prompt(深色代码块),用户改一个字符立刻看到结果,复制前零意外
  • 手机适配:表单单列、按钮全宽(沿用已修样式)
  • 改动范围:templates/开始使用/*.html 5 个模板(按钮 + 表单 JS),不碰 ops.py / render 数据层
边界确认:「复制数据/复制日志」保持纯数据(5 段 JSON / 6 段日志),不进表单——它们是存档/排障用途,不是执行指令。
