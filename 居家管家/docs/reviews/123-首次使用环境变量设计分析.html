SM8 首次使用 · 第一性原理分析

环境变量引导缺失 · 完整流程梳理

三个问题的代码级回答 + 现状流程 + 改造建议(待拍板)

1首次使用有没有引导用户配置环境变量?

结论:没有。环境检测 ops.py env_check_payload() 确实读取了 SKILLS_DB_PATH 并返回其状态(第 50/61 行),但 first_use_wizard.html 模板的「环境检测」卡片只渲染了 OS / Python / 数据库路径 / 目录可写,没有渲染 env 状态字段——用户根本看不到「SKILLS_DB_PATH 未设置,将使用默认 D:\.db」这类信息,更谈不上引导配置。

换句话说:检测逻辑在,展示断了,引导环节完全缺失。用户会看到数据库路径直接是 D:/.db/...(fallback),但不知道为什么、也不知道可以改。

2引导配置后,HTML 复制 prompt 用真实路径?

合理,而且就该这么做。你的直觉完全正确:
① 首次使用流程前段引导用户配置环境变量(一次配置,全局生效)
② 后续渲染 HTML 时 db_path 来自 DB_PATH 运行时解析(env 优先)——prompt 自然显示用户真实配置的路径
③ 复制出去的 prompt 带真实路径 → 空白 session 的 AI 拿到后路径也是对的,链路闭环

这也顺带解决了上一个问题:prompt 里不该出现写死的 fallback 假路径。

3当前完整流程是什么?

1
安装(一次性 · SKILL.md §安装与配置)
用户复制「一键安装」prompt → AI 检查 Python → 引导配置环境变量 → 显示配置 → 告知改目录方法。但这是 SKILL.md 文档流程,HTML 里没有对应环节
2
⚠️ 断点:环境变量配置
文档说「引导我配置环境变量」,但首次使用 HTML 没有渲染 env 状态、没有配置引导按钮——用户可能带着 fallback 路径直接建库
3
环境检测 cli.py check
OS / Python / 目录可写 / DB 状态(env 状态已检测但未展示)
4
路径确认
展示 db_path(默认即确认)→ 用户确认 → 不静默
5
建库 + 建分类 cli.py init
幂等:已有库/已有分类 → 跳过;种子 60 节点(8 顶级 + 52 二级)
6
状态确认 cli.py init-status
未初始化 / 库已建 / 已初始化
7
渲染向导 HTML first_use_wizard.html
6 步步骤条 + 环境信息 + 建库结果 + 下一步按钮(复制 prompt → AI)
8
完成 / 错误回执
完成 → 提示录第一批(拍物品);失败 → 错误回执 + 一键重试
核心断点:环境变量配置是「文档承诺但 HTML 断链」——SKILL.md 安装章节要求引导配置,但首次使用 HTML 既没显示 env 状态,也没给配置入口。

+改造建议(待拍板)

环节现状建议
环境检测卡片OS/Python/路径/可写(无 env 状态)增加「环境变量」卡片:显示 SKILLS_DB_PATH / HOME_PHOTOS_DIR 当前值或「未设置(走默认)」
配置引导无env 未设置时,「开始初始化」旁加「先配置环境变量」按钮 → 复制配置 prompt(如 setx SKILLS_DB_PATH "D:\2Study\StudyNotes\.db")→ AI 引导配置
路径来源prompt 带运行时路径(已修)保持运行时解析;若用户改了 env,重新 check 后路径自动更新
幂等提示已初始化 → 跳过保持;已初始化态可加「查看当前配置」入口(展示 env + 路径)

改这 3 处后,「首次使用」从文档到 HTML 全链路闭环:检测 → 展示 env 状态 → (可选)引导配置 → 确认路径 → 建库 → 回执。
