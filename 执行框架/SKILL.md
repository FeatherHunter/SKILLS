# 执行框架（AI 操作手册）

用户定制的「执行前 / 执行中 / 执行后」三项工作要求，落地为可加载 SKILL。规范本体：`docs/agents/execution-framework.md`（零冲突，本 SKILL 是操作速查版 + 模板 + 示范）。

## ⭐ 核心心法

> **AI 停在 60% 不是能力问题，是「对齐机制」缺失。** 六个保真手段的本质：把隐含的、自证的、未说出口的，全部显式化、外部化、给用户审（`docs/agents/delivery-fidelity.md`）。

## 一、执行前（五段式）

### 1. 告诉起点（对齐起点状态）

任务开始前收集四行起点（模板）：

```
1、最终目标（要做什么）：
2、当前进度（目前想到哪一步）：
3、经验水平：新手/有经验/专家
4、明确告知哪些地方不熟悉：
```

**大白话原则**：技术点（注入器/占位符/pip 等）对新手要解释到「一个没参与上下文的人也能判断」的程度。

### 2. 发现盲区（四类必查）

1. **遗漏的关键变量**——还有什么变量没考虑到？
2. **潜在的风险**——什么会翻车？
3. **容易忽略的影响因素**——什么小事会放大？
4. **需要提前决策的点**——什么现在不定以后会卡？

产出：结构化盲区清单（map 级 → map 正文「盲区清单」区；任务级 → 汇报给用户）。

### 3. 采访澄清（grilling 四连问）

禁止只问「你要 A 还是 B」。**每个问题必须先给背景**（来龙去脉/为什么问/每个选项含义与代价）：

- **反例**：「什么情况下这个方案是错的？」
- **边界**：「这个做到什么程度算过头？」
- **验收**：「你拿到手会先检查什么？」
- **历史**：「之前类似的东西你哪里不满意？」

### 4. 原型验证（先做原型再定方向）

1. 给出 **2~4 个方向**（差距要大，不要同质选项）
2. 快速验证思想（最小原型/示例）
3. 用户选择和反馈
4. 几轮后逐步收敛

### 5. 执行计划

非平凡任务动手前给用户决策清单 + 计划：

1. 明确步骤（分几步）
2. 时间安排（每步何时完成）
3. 所需资源和工具
4. **交付物和验收标准**（可勾选、可验证，写进 ticket）
5. 风险和应对方案

## 二、执行中（记录偏离）

实时记录，不等到最后才补：

1. 遇到了什么新的情况？
2. 为什么改变方案？
3. 做了哪些关键决定？
4. 对结果的影响？

**落地**：每个 ticket 的闭环评论（close 前）必含「偏离记录」区；map 级 = 决策发生即时更新 Decisions so far。

## 三、执行后（四步门禁 · 缺一不 close）

### 1. 过程复盘

1. 整体步骤回顾
2. 使用的资料和工具
3. 遇到的困难
4. 解决思路

### 2. 确认理解

对关键决策逐条解释：关键概念（大白话）/ 为什么这么做 / 其他可行方案（当时没选什么，为什么）/ 取舍权衡。

### 3. AI 反向考验

AI 出题检验用户理解（防假验收：点头 ≠ 理解）。四种题型按复杂度选 1~4 种：

- **选择题**：关键决策的变体场景，哪个对？
- **判断题**：一个说法，对还是错？
- **简答题**：用一句话解释某个概念/为什么这么做
- **案例题**：给一个新场景，用户判断该怎么走

出题原则：考「决策的理解」不考「实现细节」；基于本任务真实决策，不用抽象题库。

### 4. 答明白再交付

1. 回答正确 → 确认理解无盲区 → 确认交付（close ticket / close map）
2. 回答错误 → 补讲对应知识点 → 重新出题验证 → 再交付

**门禁**：用户没答对，不 close。

## 四、交付保真三问自检（每次交付前必做）

交付任何东西前，把答案**写出来给用户看**：

1. **我做了什么假设？**（列出来，用户一眼看出哪条是错的）
2. **哪些是我自己拍的板？**（本可问但没问的）
3. **什么算成功？**（我理解的成功标准，与用户核对）

配套：验收标准进 ticket（手段 4）/ verifier 独立审查（手段 5）/ 小步交付 + 里程碑确认（手段 6）。完整见 `docs/agents/delivery-fidelity.md`。

## 五、常见偏离记录模板

```
### 偏离记录
- 新情况: <发生了什么>
- 改方案原因: <为什么>
- 关键决策: <定了什么>
- 影响: <对结果/进度/范围>
```
