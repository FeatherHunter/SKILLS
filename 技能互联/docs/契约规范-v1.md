## 1. 身份

| 项 | 值 |
|---|---|
| 中文名 | 技能互联 |
| 英文名 | Skill Link |
| frontmatter | `disable-model-invocation: true`（基础设施型，不自动唤起、不在用户手动触发列表） |
| 定位 | 跨技能数据契约层 Base Skill（与公共组件平级：公共组件管渲染，技能互联管数据） |

## 2. 执行者（已拍板）

- 用户复制 prompt → **AI 执行**
- AI 读契约 → AI 调 skilllink-read → AI 理解/合并 → AI 注入 HTML
- AI 也会执行脚本（功能强大，能读黑盒）

## 3. 注册表（每技能声明「我能提供什么」）

字段（4 项，无版本号——AI 看字段自适应，不需要）：

| 字段 | 说明 |
|---|---|
| 域名称 | 机器标识（如 sleep） |
| 中文名 | 人类可读（如 睡眠） |
| 一句话说明 | 帮 AI 判断该域适不适合当前场景 |
| 字段列表 | 每字段：名字 / 类型 / 单位 / 说明 |

## 4. 字段类型（4 种）

| 类型 | 含义 | AI 怎么处理 |
|---|---|---|
| 数字 | 如睡眠分钟 | 可直接算 |
| 日期 | 如 2026-08-10 | 能比先后 |
| 文字 | 如物品名 | 名称标识 |
| 自由文本（text） | 如备注 OCR 原文 | AI 自己读 + 用户确认（黑盒） |

## 5. 统一信封（所有技能返回用同一盒子）

```
办成了          ← 查数据成功了吗（true/false）
来自哪个技能     ← 谁给的
查的什么         ← 数据类型（域）
查询情况         ← 开始日期 / 结束日期 / 生成时间
数据            ← 真正数据，一行一条（数组）
```

信封不带版本号（格式由技能互联 Base 固定，无版本变化场景）。

## 6. 失败与降级（时效性）

| 情况 | 信封内容 | AI 行为 |
|---|---|---|
| 对方今天没记录 | 办成了=true · 数据=[] | 如实说「该技能今天没数据」 |
| 对方没接入互联 | 办成了=false · 错误=「未接入」 | 降级：告知用户 / 尝试对方唤醒词对话式查 |
| 对方命令执行出错 | 办成了=false · 错误=具体原因 | 降级：不阻塞用户主操作 |
| 查的域不存在 | 办成了=false · 错误=「没有这个域」+ 现有域清单 | AI 看清单改问正确域（自救路径） |
| 自由文本读不准 | 正常返回 text 原文 | 用户确认环节兜底（中/低置信必确认） |

核心原则：**联动是加分，不是绑架**——失败就回到原体验，绝不让用户觉得系统卡死。

## 7. 命令

- 命令名：`skilllink-read`
- 命令真身住在技能互联 Base（各技能只放注册表 PUBLIC_DOMAINS）
- 两种用法：
  - 问「你能提供什么」：`skilllink-read --skill <技能> --what`
  - 实际查数据：`skilllink-read --skill <技能> --domain <域> --from <开始> --to <结束>`
- 身份双信号：命令名 skilllink + 路径「技能互联/」都指向 Base

## 8. 各技能接入形态

```
技能互联/
  skilllink.py        ← 命令真身（Base 提供）
  skill_registry.yaml ← 技能名 → 路径 + DB 路径
  check_public_contract.py ← 校验器（#273）
  ...
<技能>/
  PUBLIC_DOMAINS.py   ← 只放自己的注册表
```
