核心结论:HTML 的 JSON 输出是 v3.0 外壳 + v1.x 内核的混合体。外壳(video_ops / time_segments 双字段)对齐 spec,但内核——video_ops 里塞了 5 个该删的 op、段 ops 命名与校验白名单打架、schema_version 没写——这些是真正"不对齐规范"的地方。没有信息遗漏(HTML 上所有可填字段都进了 JSON),问题全是位置 / 命名 / 存在性问题。

三、video_ops 内容 严重偏移

spec §5 字段对照表规定:trim-head / trim-tail / cut-middle / pin-range / target-duration 这 5 个 op 应当消失(由 time_segments 边界等价表达)。

但 collectVideoOpsForVideo(4979-4983)的 legacyOps 数组原封不动包含全部 22 个 op,包括这 5 个该消失的: 

const legacyOps = ['trim-head','trim-tail','cut-middle','pin-range','target-duration',
  'speed-up','slow-down','reverse','mute','fade-in','fade-out','color',
  'add-bgm','replace-audio','opening-text','insert-image',
  'asr-transcribe','asr-burn','asr-speaker',
  'audio-denoise','audio-separate','audio-diarize','voice-filler-removed'];
发现 3 · 偏移 用户在 HTML 上勾选 trim-head/trim-tail/cut-middle/pin-range/target-duration,这些 op 仍会被序列化进 video_ops——直接违反 spec §5/§12。spec §12 明确写「不引入 cut-middle/pin-range/trim-head/trim-tail(被新结构替代)」。
发现 4 · 偏移 + spec 自身歧义 fade-in/fade-out。spec §5 说「视频首尾淡入淡出归 video_ops.fade-in/out(整段型)」——这两个该留在 video_ops。HTML 实际留在 video_ops ✅。但 spec §7 校验规则 validSegmentOps 里也列了 fade-in/out?不,§7 写的是 ['mute','speed-up','slow-down','reverse','color-grade']——spec 自相矛盾(§5 留 fade-in/out 在 video_ops,但 §7 没把它们列进段内合法 op,也没列进 video_ops 合法清单,因为 §7 压根没校验 video_ops 的 op 名)。这点 spec 自身有歧义。
发现 5 · 偏移 color vs color-grade。三处命名不统一:spec §4 video_ops 用 color;spec §7 段内合法 op 用 color-grade;HTML collectVideoOpsForVideo(4994-4995)用 color+style;SEGMENT_OPS_SCHEMA(5248)段内用 color+preset。
发现 6 · 偏移 voice-filler-removed vs voice_filler_removed。HTML legacyOps(4983)用连字符 voice-filler-removed;SEGMENT_OPS_SCHEMA(5255)用下划线 voice_filler_removed。段内与整段 op 同一概念两种拼写。
发现 7 · 偏移 opening-text / insert-image。spec §5 标注「待实现」+ §12「不引入 opening-text/insert-image 的 event 表达(留待 Phase H)」。但 HTML legacyOps(4981)已包含并实现(5004-5017 收集 text/duration/file/at)。HTML 跑在了 spec 前面。

📋 待确认决策:5 个 legacy op 的处置

spec §5/§12 明确 trim-head / trim-tail / cut-middle / pin-range / target-duration 应当从 video_ops 消失,由 time_segments 的边界等价表达(例:trim-head sec=5 → time_segments[0].start_sec = 5)。

但 HTML 当前仍把这 5 个 op 序列化进 video_ops,且 HTML UI 上这 5 个 op 的 checkbox 还存在(1032-1046 图片灰显样式还引用它们),意味着用户仍能勾选。

请选择处置方案:

A · 严格删除(推荐) UI 上这 5 个 checkbox 也一并移除,用户只能用 timeline 框选表达"掐头/去尾/切中间/只保留"。彻底贯彻 spec 的"几何方式表达保留片段"。collectVideoOpsForVideo 的 legacyOps 剔除这 5 个;migrateLegacyIntent 把旧文件里的这 5 个 op 转成 time_segments 边界。
