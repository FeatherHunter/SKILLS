3 · 3 个修复选项(用户在选)

选项做法权衡
A · 保持 [feat/fix(skill名)] 新 commit 继续用 feat/fix/chore 风格,去掉 Phase 编号(更 match 仓库) ✓ Conventional Commits 标准
✓ 未来 git 工具兼容(commitizen 等)
✗ 与 SKILLS 仓库主流 [skill名] 风格不一致(可选断行)
B · 切到 [skill名] 新 commit 改 [私家大厨] 描述 风格 ✓ 与 SKILLS 仓库主流一致
✗ 33 个历史 commit 仍用 [feat/fix(私家大厨)] 风格 → 永久不一致
C · 完全统一(改历史 commit) interactive rebase 改 33 个 commit 标题 ✓ 风格完全一致
✗ 改历史 commit 是危险操作(已 push 到 origin)
✗ 其他 agent 已基于这些 commit 写代码 → 改 hash 会破坏下游
我的建议:选 A
  • 保持 [feat/fix(skill名)] 描述 风格(conventional commits 标准)
  • 去掉 Phase X.Y 编号(改 AI 内部追踪,不污染 commit 历史)
  • 历史 33 commit 不动(已 push + 改 hash 风险大)
如果你选 B(match 仓库主流):新 commit 开始 [私家大厨] xxx 格式。我会立即应用。
