1 · 直接回答

你的猜测是对的!场景 2 = "复制 prompt 给 AI"模式(沿用 P1-2 单工铁律)。
不是 form 自动提交 · 不是 fetch 调本地 proxy · 不是浏览器的"应用"按钮。

2 · 为什么不能 "form 自动提交"?

§04 原则 10 · HTML 单工铁律(总纲): 
Layer 0 事实:
  ① LLM = HTTP API(远程服务)
  ② HTML = 浏览器渲染的文件(无服务端能力)
  ③ 当前架构 = 没有服务端中转 + 只有 IDE 进程内 agent
推导链:
  ① + ② + ③ → HTML 与 LLM 之间没有通路
  唯一路径: 用户手动承上启下
            HTML → 复制 → 粘贴 → AI 执行
设计约束: 所有"过程型"HTML 必须设计为"复制模板"
HTML file:// 协议不能:
  • ❌ fetch() 跨域(浏览器同源策略)
  • ❌ POST 表单(file:// 不能 POST)
  • ❌ 调本地 CLI(用户机器配置不可控)
  • ❌ 暴露 API key(用户端 vs 服务端)
→ HTML 永远只能 "复制 prompt 给 AI",不能直接提交。

3 · 场景 2 · 实际工作流设计

Step 1 · 用户打开批量编辑页

打开 batch_edit.html · 3 个 tab:

  • Tab A · 食材列表 — 调用 ingredient_manager.search "X" 列出某菜的所有食材
  • Tab B · 步骤编辑 — 调用 step_manager.list "X" 列出所有步骤
  • Tab C · 标签管理 — 调用 season/flavor/category manager 列某菜的标签

每个 tab 显示当前 DB 状态(只读视图)。

Step 2 · 用户编辑表单(具体数据)

用户在 HTML 内编辑字段值。例如:

<tr data-id="ing-uuid-xxx">
  <td><input value="五花肉" /></td>
  <td><input value="300" /></td>     ← 用户改成 300
  <td>g</td>
</tr>

⚠️ 这里只是浏览器内 DOM —— 不影响 DB。

Step 3 · 点 "复制修改 prompt"(应用按钮变 prompt)

点击 "📋 复制修改 prompt" 按钮,JavaScript 收集所有修改,生成一段给 AI 的提示词:

[批量编辑修改意图 · 2026-07-27 14:32]

请按以下修改调用 ingredient_manager update:
1. 食材 ing-uuid-A:
   - quantity: 100 → 300
2. 食材 ing-uuid-B:
   - quantity_text: "50g" → "100g"

来源:私家大厨 batch_edit.html → ingredient_manager update

[给 AI 的指令]
加载「私家大厨」技能,用 ingredient_manager.py update 子命令按上面修改。
改完告诉我。

Step 4 · 用户粘贴给 AI

  1. 用户复制剪贴板
  2. 切到 AI 对话
  3. 粘贴 → AI 解析这段 prompt
  4. AI 调 ingredient_manager.py update 多次
  5. DB 实际写入
  6. AI 回报结果

Step 5 · 用户回 batch_edit.html 看新状态

点击"🔄 刷新"按钮 → 调 ingredient_manager.search 重新读 DB → 显示新数据。

5 · 这个方案的优势 vs 劣势

✅ 优势:
  • 遵守单工铁律 — HTML 不直接调任何 AI,符合总纲 §04 原则 10
  • 符合 P1-2 已建立的"复制 prompt"心智模型 — 用户已经习惯(烹饪模式"复制做菜 prompt"已用)
  • 0 配置 — 用户无需安装任何本地服务
  • 可复用现有 manager CLI — Q3 argparse 重写后,prompt 解析更准
❌ 劣势:
  • 需要 2 步(用户改 → 切 AI 粘贴) —— 摩擦大于"一键保存"
  • 不能 undo — 用户改完忘了粘贴就丢了
  • 不能并发 — 用户编辑期间 AI 改了同一行会冲突
这些劣势可被缓解:
  • 留存 localStorage(chrome.html 已用)暂存编辑状态
  • 在 prompt 顶部加 "如已修改请忽略" 防并发
  • HTML 上加 "上次修改:" 时间戳,降 prompt 误用风险
