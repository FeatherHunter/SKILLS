Q1

tips 表为什么为空?你说 add 强制最少 1 个 tips

实测结论:你记忆有误。实际实现是"warning",非强制。
  1. SKILL.md 设计意图:"tips ≥ 1"(你的想法)
  2. 实际实现:validators.validate_tip_minimum() 返 status: warning(不是 error)
  3. recipe_import.add_tips() 写的是 if not tips: return(静默跳过)
  4. CLI tip_manager.py add 只校验 4 个字段(recipe_id/--content/--scope/--category/--priority)——没有"至少 1 个"的硬约束
tips 表空的原因:录入辣椒炒肉时,JSON 数据的 tips 字段就是空数组 [](不是 AI 手动 add 过 tips 后再删除,是录入时就没填)。
修复方案(2 选 1):
  1. 方案 A · 最小:改 add_recipe() 在 recipe_import.py 检测 not data.get("tips") → 报 status: error 阻断 import
  2. 方案 B · 治本:改 validate_tip_minimum() 把 tip_data 是单个调用(不是 list)的判断也纳入校验 + tips list 为空时 error 而非 warning
推荐方案 A(最小入侵,改动 5 行)。
Q2

step_techniques 的要求也是不能为空 — 真?

实测:也是"warning",不是 error。你的设计意图与实现不一致。
recipe_import.add_techniques(): 
if not techniques:
    return
静默跳过 → techniques 表 0 行。
修复方案:同 Q1 — 把 recipe_import.add_recipe() 加硬约束:
  • if not data.get("tips"): error "tips 必填,最少 1 条"
  • if not data.get("techniques"): error "techniques 必填,最少 1 条"
Q3

两个 ❌ 未知操作:list —— step_ingredient / technique

根因:这 2 个 manager 只有 list-by-step / list-by-recipe / list-by-ingredient 子命令。没有 list 裸子命令。用户写 list 走 main() 的 else 分支 → emit(error("未知操作:list"))。
3 方案对比:
方案做法取舍
A · 别名兼容在 main() 加 if action == "list" 时按参数推断到底是 list-by-recipe 还是 list-by-step🟡 隐式,易误判,破坏一致性
B · 加 list-by-recipe / list-by-step 别名main() 加 "list" 映射到 "list-by-recipe"(需要 recipe_id)🟠 简单,但 --list --help 仍显示旧名
C · 改 argparse 模式重写 main() 用 argparse 子命令 + type 校验 + 友好 --help✅ 治本,顺便修 Q4
推荐方案 C · argparse 子命令:
  1. 重写 step_ingredient_manager.py / technique_manager.py 的 main()
  2. 改 if action == "list-by-step": → parser.add_subparsers().add_parser("list", aliases=["list-by-step"], help="...")
  3. 所有 flag type 校验 + choices(食材分类/关系类型等)
  4. 用户跑 manager.py --help 看到所有子命令 + 合法值
  5. 同时修 Q4(参数错误友好提示)+ Q5(13 个可用化)
Q4

add 时错误参数不应被静默忽略

实测重现(我刚刚污染 DB 验证): 
python3 ingredient_manager.py add 230ce6e5... \
  --name test2 --quantity 100 --unit g \
  --category "无效分类" --quantity_text 100g \
  --sequence 99 --is_optional 0 --substitute "无"

→ ✅ 食材添加成功!"test2 100g"
  ← 无效分类被静默接受!
实际后果:DB 多 1 行 test2(我已清理)。
根因:
  1. ingredient_manager.py 不用 argparse(实测 grep 0 命中)
  2. 手写 args.get("--xxx") 解析,无 type / choices 校验
  3. 调 validators.validate_array_enum() 但只对 ingredients.category 的 11 类合法值校验,未强制校验 is_optional 等
  4. category "无效分类" 不在 11 类合法值中,但 validators 未触发(check_args 里没调用)
修复方案(同 Q3 方案 C):
  1. 每个 add() 函数顶部加 validators.validate_xxx(...) 校验
  2. 或用 argparse(type= + choices= + required=)自动校验
  3. 校验失败返 status: error + field: + current_value: + expected: + how_to_fix:
