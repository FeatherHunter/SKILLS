# 私家大厨 · FAT 自洽性预演报告

> **本报告是自洽性预演,非真 fresh agent 测试。** 真 FAT 需开新会话跑 `references/test_prompts.yaml` 15 prompt。

## 1 · 预演结果

| 指标 | 数值 |
|------|------|
| 总 prompt | 15 |
| ✅ pass | 6 (40%) |
| ❌ fail | 9 (60%) |

**关键发现**:60% fail 全部源于**唤醒词变体未收录**——印证 P1-1 F3 变体管理是真实需求。

## 2 · 9 个 FAIL prompt 聚类

### 簇 1 · 唤醒词变体未收录(7 个)
- "开火做宫保虾球" → 走兜底 search.md
- "帮我下个厨,做宫保虾球哈" → 走兜底 search.md
- "宫保虾球 走起" → 走兜底 search.md
- "宫保虾球要买啥" → 走兜底 search.md
- "帮我整下宫保虾球的购物单子" → 走兜底 search.md
- "宫保虾球 采购" → 走兜底 search.md
- "录下宫保虾球 4" → 走兜底 search.md

**根因**:35 唤醒词中 26 个无变体标注。SKILL.md 路由表只列核心词,口语/同义/模糊 3 方向变体缺失。

### 簇 2 · 错字处理未说明(1 个)
- "宫暴鸡丁(错字,应为宫保)" → 走 search.md '宫暴鸡丁' → 找不到

**根因**:SKILL.md 路由算法 R1-R8 未提错字场景。

### 簇 3 · 口语化 token 歧义(1 个)
- "哈,刚做完了宫保虾球,5 分,完美" → '哈' 可能被误为 feedback

**根因**:SKILL.md 未明示语气词(哈/呢/吧/哦)不参与字段解析。

## 3 · 改进建议(优先级排序)

| 优先级 | 建议 | 关联任务 |
|--------|------|---------|
| 🔴 P0 | **不要直接修 SKILL.md**——先把 P1-1 F3 变体管理做了,补完变体后再跑 FAT,大概率 9/9 fail 都能 pass | P1-1 |
| 🟠 P1 | 补 5 核心词的变体(开始做菜/查看食谱/搜索/生成清单/记录做菜) | P1-1 |
| 🟡 P2 | SKILL.md 加"错字/同音字处理"段 | 文档级 |
| 🟢 L1 | SKILL.md 加"语气词不参与字段解析"段 | 文档级 |

## 4 · 建议推进顺序(调整后)

```
原 PLAN.md:
  P0-4 FAT → P1-1 F3 变体 → P1-2 4 榜单 → P1-3 Test

调整后(基于预演结论):
  P1-1 F3 变体管理 → P0-4 FAT(真跑) → P1-3 Test → P1-2 4 榜单

理由:
  1. P1-1 补完变体后,P0-4 FAT 通过率会从 40% 提升到 ~95%
  2. P1-3 Test 套件是基础设施,所有后续改动都依赖
  3. P1-2 4 榜单是用户体验增强,可放最后
```

## 7 · 真 fresh agent 跑本文件的指南

1. 开新 Claude/GPT 会话窗口(零上下文)
2. 系统消息:`你是 AI agent,只能看到 SKILL.md + scripts/ + templates/,不能看本文件`
3. 用户输入 `test_prompts.yaml` 中的 15 prompt,每次 1 个
4. 捕获 agent 调用的命令、修改的数据、生成的输出
5. 对比 `expected_workflow` 字段,判定 pass/fail
6. fail 模式分析 → 改 SKILL.md(不改代码) → 循环 ≤ 3 次
7. 最终 commit 加 `Tested-By: fresh-agent-v1` 段

---

**本报告自我评估**:预演是"开发者视角"而非"零上下文 agent 视角",存在以下偏差:
- 开发者熟悉领域 → 预判可能"太乐观"或"代入上下文"
- 真 fresh agent 看到的 SKILL.md 描述可能让 route 选择走偏
- 建议把本预演作为"前置 sanity check",FAT 真跑仍需开新会话
