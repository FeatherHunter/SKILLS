3 · 推进前第一性反思(3 个反第一性发现)

"按顺序推进，推进前需要从第一性原理出发" — 用户授权后的反思
发现 A · Phase 1.7a _N 后缀 = 反第一性(强烈建议取消)
矛盾：V3 强制 _N 后缀 vs HELP 本质 = 最新快照。
HELP 价值
快照当前场景资产(让用户知道技能"今天能做什么")
旧 HELP 价值
0(场景资产已更新，旧 HTML 是误导)
真实并发场景
1 秒内连发 2 个 HELP 命令(极小概率)→ 用 latest.html 软链 + 单文件覆盖即可
V3 设计
为"数据/过程" 设计(每次触发产生新数据)；HELP 不属于这种
建议：取消 Phase 1.7a。改为加 latest.html 软链给 AI 用（永远指向最新副本），旧副本保留 1 个被覆盖。
发现 B · Phase 1.7b env 迁移 = Breaking Change 风险(建议双轨兼容)
风险：SKILL.md "一键安装"段要求用户设 $CHEF_OUTPUT_DIR。直接换名 = 现有用户配置全失效。
建议双轨兼容（优先级）：
$SKILLS_DATA_DIR > $SKILLS_DB_PATH > $CHEF_OUTPUT_DIR > D:/CookHub fallback
发现 C · P0-2 F2 真正问题不是锚点，是 SKILL.md 误导 AI(重要)
之前判断错：我之前把 F2 当作"加 section 锚点"。但 grep 后发现recipe_view.html 无锚点 + SKILL.md 第 138-150 行明确写：
"AI 调 recipe_manager show 拿全量后,从全量截取对应 section 给用户"
— SKILL.md 第 138-150 行(原文)
这是写给 AI 看的文档,它直接教 AI 走文字截取 = 违反原则 11。
正确修复：改 SKILL.md 第 138-150 行,明确说"AI 调 recipe_render.py render X + 推 HTML 给用户(用 <media> 标签)"。
锚点是 nice-to-have(用户体验),不是修复。HTML 全文已包含食材/步骤/营养/背景,AI 只需 invoke HTML + 推文件,不需要截取。
