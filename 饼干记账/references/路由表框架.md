# 路由表编号框架(公共层 · 实施期全表一次性连续编号)

> 来源:G2 决议(军规 3:路由表全表一次性连续编号,防 7 域并行冲突)+ G5 决议(description 矩阵)。
> 实施规则:编号由公共层一次分配完毕(方案 A),各域实施只填自己行段,不改他人编号。

## 编号方案

全局连续编号 `N`,按域顺序分段分配(每域预留区间,后续新增场景在域区间内追加):

| 域 | 编号区间 | 行内容(每行) |
|---|---|---|
| 开始使用 setup | 1-10 | 唤醒词 / 功能 / CLI 命令 / 输出形式 |
| 写入 write | 11-50 | 同上 |
| 查询 query | 51-80 | 同上 |
| 分析 analysis | 81-110 | 同上 |
| 目标 goal | 111-120 | 同上 |
| 账户 account | 121-130 | 同上 |
| 联动 link | 131-140 | 同上 |
| HELP | 141-145 | HELP 唤醒词(4 条)+ 保留 |

## 行内容契约(每行)

| 列 | 内容 |
|---|---|
| # | 全局连续编号 |
| 唤醒词 | 中文(场景入口) |
| 功能 | 一句话 |
| CLI 命令 | `scripts/{域}/cli.py <sub> [参数]`(v2.0 三域/七域入口) |
| 输出形式 | HTML(查询/分析)/ 文字回执(写入) |

## 变更规则

- 新增唤醒词:在所属域区间内追加编号,不重排既有编号
- 删除:编号作废不回收(防引用漂移)
- SKILL.md 路由表 ↔ scenes 汇总 wake_word ↔ description 矩阵三处对照(门禁 A 第 2 层)
